# ЕИС: безопасное восстановление HTTPS-доверия на Windows (31.10.2026)

## Подтверждённый результат оператора

На Windows: **103 passed**, затем `SERVICEIT_EIS_STAGE=OFFICIAL_RSS_READ`, `ERROR_CODE=EIS_TLS_TRUST_FAILED`. Это означает, что программа дошла до сетевого запроса, но **не получила и не обработала живую RSS**. Ни одного коммерческого лида, ИНН покупателя и отправки в Битрикс24 не подтверждено.

## Почему старый Python не доверял сертификату

После 04.07.2026 публичная часть закупочного портала перешла на сертификат Минцифры России, см. информационный канал Казначейства: https://t.me/s/gis_eiszakupki/3140 . HTTPX 0.x при `verify=True` использует CA из `certifi`, а не пользовательские/системные доверенные корни Windows. В Яндекс.Браузере сайт может открываться за счёт собственного доверенного набора, что не доказывает доверие **Windows**.

В обновлённом `leadpilot.eis_rss` на Windows создаётся `ssl.create_default_context()` и он передаётся в HTTPX как `verify=context`. Python на Windows подгружает CA из системных хранилищ `ROOT` и `CA`. TLS-верификация и имя хоста остаются обязательными. На не-Windows без пользовательской CA сохраняется стандартный режим HTTPX/certifi.

Официальная документация по SSL-контекстам Python: https://docs.python.org/3/library/ssl.html#ssl.SSLContext.load_default_certs ; описание SSL HTTPX: https://www.python-httpx.org/advanced/ssl/ .

## Если доверия Windows всё ещё недостаточно

**Не загружать корневые сертификаты из чатов, GitHub-проектов, Telegram-архивов или случайных ссылок. Скрипт не устанавливает сертификаты автоматически.**

1. На компьютере открыть официальную страницу [Госуслуги — поддержка российских сертификатов](https://www.gosuslugi.ru/crt) или [корневые сертификаты Казначейства](https://roskazna.gov.ru/gis/udostoveryayushchij-centr/kornevye-sertifikaty) и сверить источник.
2. При необходимости вручную установить подлинные **корневой и выпускающий сертификаты Минцифры** по инструкции для Windows. Для пользователя без прав администратора предпочтительнее `Текущий пользователь`; установка в `Локальный компьютер` может требовать согласования администратора. Это меняет системное доверие к сайтам и должно быть осознанным решением пользователя.
3. Альтернатива установке: сохранить самостоятельно проверенный официальный сертификат `.crt` / `.cer` (DER) или `.pem` и указать `-CaBundle 'ПОЛНЫЙ_ПУТЬ_К_ПРОВЕРЕННОМУ_СЕРТИФИКАТУ'`. Файл будет загружен **только в контекст одного HTTPS-соединения**, не в хранилище Windows. PEM может содержать несколько подлинных сертификатов одной цепочки; не собирать цепочку из сомнительных источников.
4. Повторно запускать acceptance. Если появится `EIS_HTTP_STATUS_404`, `EIS_RESPONSE_NOT_XML` и т.п. — проблема больше **не** в TLS: нужно сверить действительную ссылку RSS в официальном интерфейсе. Ссылка в пакете acceptance — **гипотеза, не подтверждённый адрес**.

Официальный тест настройки доверия в браузере, опубликованный ЕИС: https://rus-ssl.zakupki.gov.ru/ (открывать вручную, это не RSS и не источник лидов).

## Зафиксированные ограничения

Не применять `verify=False`, `curl -k`, `--insecure`, перехват TLS и автоматические обходы блокировок. Код не меняет Windows Root Store, не загружает сертификаты самостоятельно, не пишет в CRM, не обходит CAPTCHA и не отправляет сообщения.

**После успешного TLS ещё отдельно проверяются** реальный RSS-адрес, XML, предмет услуги, ИНН покупателя, ФНС микро/малое, Москва/МО, актуальность срока, CRM-дубли/стоп-листы и разрешение менеджера. Пока `qualified_leads=0`.
