## Более точная стратегия пилота

ФНС официально поддерживает поиск и выборку субъектов МСП по региону, категории и виду деятельности. Источники:
- https://rmsp.nalog.ru/ — поиск и Excel-export;
- https://www.nalog.gov.ru/opendata/7707329152-rsmp/ — официальные ежемесячные открытые XML-данные;
- https://www.nalog.gov.ru/rn77/related_activities/regbusiness/reestrquetoin/ — FAQ об использовании расширенного поиска.

Ищем **ЮЛ с категорией «Микропредприятие» или «Малое предприятие»**, регион **Москва (77) / Московская область (50)**. Внутри этих сегментов тестируем отдельные ОКВЭД торговли, ремонта, услуг, медицины, производства и прочих организаций с потенциальным использованием 1С. Отрасль/ОКВЭД — не доказательство спроса.

### Новый офлайн-модуль

`leadpilot.sme_first_discovery` принимает **небольшую** официальную Excel-выгрузку, сохранённую оператором после поиска ФНС. Повторно использует проверенный парсер ФНС и:
- удостоверяет дату среза, ИНН/контрольную сумму, категорию микро или малое, тип «Юридическое лицо», код региона 77/50, основной ОКВЭД;
- исключает **все 18 уже проверенных ИНН** по двум отдельным локальным отчётам, не объявляя найденные только по вакансии;
- оставляет только `SIZE_ONLY_RESEARCH`: `demand_for_1c=NOT_CHECKED`, `lead_score=null`, `crm_ready=false`;
- **не переносит** телефоны, email и другие контакты даже если они есть в XLSX;
- не пишет в CRM/БД, не делает сетевых запросов, не обращается к AI;
- не перезаписывает исходные файлы, не обрезает молча список (если подходящих больше установленного лимита — ошибка с предложением сузить фильтры);
- исключает ИП на этом первом этапе из соображений строгого разделения открытых данных о юрлицах и персональных сведений предпринимателей (возможность работать с ИП отдельно рассмотрим после уточнения юридических условий).

### Как попробовать на локальном Windows

1. Открыть https://rmsp.nalog.ru/ → **расширенный поиск** (или доступные поля поиска); выбрать микро/малые компании, **регион 77 или 50** и конкретную группу ОКВЭД. Не выбирайте сразу все сферы: экспорт должно быть возможно разобрать как небольшой набор **не более 100 записей**, желательно 20–50.
2. Сохранить Excel через «Экспорт в Excel» в `Downloads`; **не** добавлять в GitHub.
3. На ветке нового Draft PR сначала запустить pytest; далее:

    .\.venv\Scripts\python.exe -m leadpilot.sme_first_discovery --xlsx "$HOME\Downloads\ИМЯ_ВЫГРУЗКИ.xlsx" --limit 50 --output exports/sme_first_size_only.json --inn-list exports/sme_first_inns.txt

4. Полученный `sme_first_size_only.json` — **список для исследования**, не очередь продаж. Даже при 50 подтверждённых микро/малых компаниях лидов CRM-ready остаётся **0**, пока не найден отдельный актуальный сигнал реальной потребности в услуге, не проверены дубли/правовые ограничения и не подтверждены допустимые способы контакта.

Данные из массовой XML-выгрузки ФНС могут быть существенно больше, чем Excel GUI; этот PR **не** выполняет автоматическое массовое скачивание/распаковку, обход ограничений сайта или автоматическое взаимодействие с ФНС. При желании XML можно исследовать как отдельный источник с тестом схемы, объёма и актуальности.

### Оставшиеся задачи для пилота

После подтверждения категории бизнеса требуется **сигнал спроса**, например публичное объявление компании об аутсорсинге 1С, опубликованная потребность в сопровождении торговой системы, закупочный запрос или вакансия 1С как *гипотеза*, а не заявка купить услуги. Для любого лида отдельная ручная проверка актуальности и правомерности корпоративного канала, дубликатов клиента/стоп-листа в Битрикс24, отдельного согласования механизма первой коммуникации. До доступа к разрешённой изолированной тестовой зоне **никакой записи в рабочий Битрикс24**.

Документы/результаты из этого PR — новый отдельный этап исследования. Первоначальные 152 теста подтверждены владельцем; новые 8 тестов нужно выполнить на Windows (ожидаемый итог **160**, но это не текущий факт). GitHub Actions runner issue #7 по-прежнему не подтверждён.

## Инцидент локального Excel-пути и исправление (31.10.2026)

После успешных **160 passed** оператор запустил `leadpilot.sme_first_discovery` со строковым именем файла в `Downloads` и получил `ValueError: Expected a small XLSX file downloaded from the FNS batch-search UI`. Это защитная проверка **до открытия workbook**; она объединяла три разные причины — файл отсутствует/переименован, расширение отличается от XLSX, размер больше 12 MiB. При этом малая московская выборка, подготовленная из загрузки ФНС в рабочей среде, реально существует: около **12,7 КБ**, 50 строк с датой реестра 31.10.2026, правильными заголовками и регионом 77. Причина на компьютере оператора **не доказана** до проверки каталога `Downloads`.

Исправлены сообщения `read_fns_xlsx`: `FNS_XLSX_NOT_FOUND`, `FNS_XLSX_INVALID_EXTENSION`, `FNS_XLSX_EMPTY_FILE`, `FNS_XLSX_TOO_LARGE`. Добавлены 5 тестов; ожидаемый общий pytest — **165**, пока не подтверждено Windows.

**Рекомендованное восстановление:** сохранить небольшой Excel «Москва — 50 микропредприятий» в папку Windows Downloads, затем после `git pull --ff-only origin feat/sme-first-fns-discovery-20261031` один раз выполнить:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/RUN_SME_MOSCOW_RECOVERY.ps1

Скрипт строго ASCII-only для Windows PowerShell 5.1, автоматически ищет файл по уникальной части имени `77_50_` (допускает браузерные суффиксы имени), показывает реальный путь/размер, запрещает подмену большой общероссийской выборкой, проверяет pytest, создаёт только новые ignored JSON/TXT. При ошибке завершится кодом 1 и надписью `SME_FIRST_IMPORT=FAILED`. При успешной обработке от 1 до 50 компаний появится `SME_FIRST_IMPORT=SUCCESS`; это **только размер бизнеса**, не доказательство спроса и не разрешение на запись в CRM.

Ни один реальный файл Excel, локальный список ИНН, персональные контакты или данные о компаниях в GitHub не добавлены.
