# Автоматическая оценка пакетов источников (все лиды) — этап без CRM-записи

## Задача

Владелец просит отказаться от ручного заполнения цветной метки у DEMO №3 и получать **автоматический Score + 🟢/🟡/🔴 для всех новых входящих сигналов**. Эта ветка соединяет несколько источников с универсальным Lead Score и планом карточки 1062 без повторной ручной работы.

## Что реализовано

- `leadpilot/serviceit_source_batch_pipeline.py` — входной контракт `serviceit-source-batch-v1`, пакет до 250 записей; безопасно группирует по ИНН, объединяет до 12 различных сигналов на компанию, дубли одного URL+сервиса отбрасывает, конфликт источников/проверок блокирует.
- Вызывает реальный `assess_lead` для КАЖДОЙ уникальной компании. Детерминированная оценка, версия `mvp-2026-10-v1`, уже присоединённый универсальный `kanban_score_badge` автоматически попадают в безопасный план CRM (Score, версия, цвет).
- Не доверяет отсутствующим проверкам: отсутствующая `company_registry`, `source`, `existing_customer`, `crm_dedup`, `stop_list`, `legal_basis`, `contact` маркируется `UNKNOWN`. Никакой цвет, включая 🟢90, не является разрешением на холодный звонок или реальную запись в CRM.
- Все операции **в текущем релизе только офлайн**, нет ключей и вебхуков, внешних HTTP, генерации GigaChat, писем, звонков, локальных журналов другого рабочего кода, `crm.item.add/update`. Безопасный вывод содержит маскированные SHA company/signal, оценку, метку, допустимость и число источников; сырой текст сигнала и контактные данные в stdout не печатаются.
- `fixtures/serviceit_source_batch_demo.json`: учебный пакет с 2 компаниями, 3 уникальными сигналами, 1 дублем.
- `scripts/RUN_SERVICEIT_ALL_LEAD_SCORE_PREVIEW.ps1`: Windows-оператор для одного локального запуска. Без InputJson берёт только учебный пакет. С `-InputJson` принимает локальный JSON по контракту, но по-прежнему ничего не отправляет в корпоративный Bitrix.

## Пример запуска после CI и merge

```powershell
$Repo = "$env:USERPROFILE\Service_IT_GitHub_Repo\Service-IT-LeadGen"
$Python = Join-Path $Repo '.venv\Scripts\python.exe'
& powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Repo\scripts\RUN_SERVICEIT_ALL_LEAD_SCORE_PREVIEW.ps1" -PythonPath $Python
```

Ожидаемый статус `SERVICEIT_ALL_LEAD_BATCH_PREVIEW`. Не нужен Bitrix вебхук. Это **подготовка к автоматизации**, а не доказательство, что новые карточки автоматически появятся в CRM.

## Что осталось до полномасштабной автоматизации на портале

1. Обеспечить реальный лицензированный источник прямых заявок, а не вакансий как доказанных продаж.
2. Проверить ФНС/ИНН, первоисточники, существующих клиентов, дубли во всей корпоративной CRM, stop/legal. Даже если внешний JSON сообщает `VERIFIED`, этот офлайн модуль НЕ подтверждает данную проверку на портале.
3. Написать отдельный корпоративный **write-адаптер** с фиксированным контрактом безопасного upsert: один авторизованный `crm.item.add/update` на все необходимые поля сразу (в том числе badge) **после** предварительного GET, подтверждения прав и уникальности, идемпотентность, журнал, readback. Пользовательский цветной badge `UF_CRM_13_SVCIT_AI_SCORE_BADGE` сейчас реально создан, но пока в DEMO #3 `EMPTY` даже после POST и ручного сохранения; исходные `UNCERTAIN` журналы нельзя сбрасывать или повторять.
4. Настроить единый **просмотр канбана** для всех через официальные настройки интерфейса, затем проверить минимум три новые тестовые карточки с 90/65/35 по одному утверждённому источнику.
5. Включать регулярный worker и реальные источники только после приёмки Микаилом, с ограничениями по спискам клиентов и контактам. Полный GigaChat-отчёт подключается отдельно от детерминированного Score.

## Границы готовности

Достигнуто: **многоисточниковый офлайн поток → объединение по компании → оценка → 🟢/🟡/🔴 → проверяемый план CRM без записи**.

НЕ достигнуто: **полностью автономная публикация в Битрикс24**, постоянный worker, живые источники и полная юридическая/коммерческая верификация. Не выдавать результаты GitHub тестов за подтверждение корпоративного end-to-end.
