# ЕИС для MVP «Сервис ИТ»: официальный RSS, проверка покупателя

## Цель по письму Микаила (30 октября 2026) и ТЗ v3.0

Нужны небольшие компании Москвы/Московской области со свежей проверяемой потребностью во **внешнем сопровождении 1С**. Не обычный агрегатор вакансий и тендеров. Каждый сигнал должен сохранять первичную ссылку, дату, предполагаемую услугу и готовиться к проверке менеджером. AI-гипотеза не является доказанным фактом.

ЕИС содержит закупки по 44-ФЗ и 223-ФЗ, в том числе госучреждений и крупных компаний. Допуск поставщиков-МСП **не означает**, что заказчик является микро/малым предприятием. Несоответствующие закупки можно рассматривать отдельно как возможное участие самой «Сервис ИТ» в тендере, но не в числе квалифицированных лидов первого пилота.

## Реализованный адаптер

`leadpilot.eis_rss`: явный одиночный HTTPS GET оригинальной RSS-ленты расширенного поиска с официального `zakupki.gov.ru`. Не используются вымышленные параметры запроса. RSS или Atom: название услуги 1С, оригинальная ссылка на извещение, дата, устойчивый ID для дедупликации. Сигналы старше 30 суток исключаются, без даты изолируются. Лимит 2 МБ, безопасная обработка XML, TLS без отключения проверки, редиректы и HTML вместо XML — ошибка, а не «ноль тендеров».

### Пример запуска (PowerShell)

```powershell
.\.venv\Scripts\python.exe -m leadpilot.eis_rss --url 'ПОЛНАЯ_ССЫЛКА_RSS_ИЗ_ИНТЕРФЕЙСА_ЕИС' --output exports/eis_run_01.json
```

Настоящую ссылку с поиском «сопровождение 1С» и регионом Москва/МО нужно скопировать **из кнопки RSS официальной ЕИС**. Образец в команде — **не рабочая ссылка**. Для оригинального XML, сохранённого с ЕИС, допускается режим:

```powershell
.\.venv\Scripts\python.exe -m leadpilot.eis_rss --rss-file exports/eis_original.xml --feed-url 'ПОЛНАЯ_ССЫЛКА_RSS_ИЗ_ЕИС' --output exports/eis_offline_review_01.json
```

Результат — исследовательские записи в игнорируемой Git папке `exports/`. Нет записи в CRM, авто-рассылок, контактов, коммерческого Lead Score или изменений VALYQON. Формальные признаки: `buyer_inn=null`, `buyer_fns_size=UNVERIFIED`, `deadline_on=null`, `crm_ready=false`, `outbound_authorized=false`, `qualified_small_business_leads=0`.

## Обязательная квалификация до передачи менеджеру

1. Открыть **оригинальное** извещение и документы на ЕИС; подтвердить внешние услуги 1С (не 1С-Битрикс и не только лицензии), дату, статус и срок подачи, регион оказания услуг.
2. Сопоставить **ИНН именно покупателя** из первичного документа с официальной выпиской ФНС. Проверить микро/малое предприятие Москвы/МО; не считать МСП-преференцию для поставщика доказательством размера покупателя.
3. Просроченные, отменённые или нецелевые закупки оставить в исследовании либо выделить в **самостоятельный канал тендерных возможностей**, не маркируя B2B-лидом малого бизнеса.
4. Проверить публичный корпоративный контакт, основание обращения, существующего клиента, историю сигналов, CRM-дубли и стоп-листы. Только тогда менеджер принимает решение. Для вручную подтверждённых ИНН и ссылок есть `leadpilot.public_1c_demand_gate` и `leadpilot.review_pipeline`.
5. В корпоративный Битрикс24 писать исключительно после согласования отдельного тестового доступа, прав, полей и изоляции. До подтверждённого интереса — Lead, затем возможная Deal.

## Приёмка источника

**Пока готов адаптер, а не подтверждена работа живой ЕИС.** Тесты `tests/test_eis_rss.py` используют синтетический RSS, проверяют XML, свежесть, дубли, доверенные ссылки и ошибочные HTTP-ответы. Реальный ответ официальной RSS из этой среды не получен. Приёмка требует реальную RSS-выдачу на машине оператора, проверяемые URL извещений, подтверждение 1С-предмета, ИНН, ФНС, статуса и даты, затем менеджерское решение. Не заявлять о 10–20 готовых лидах без данных.

Официальное описание ЕИС: https://roskazna.gov.ru/gis/eis-zakupki-gov-ru . Регламенты и сведения о СОИ: https://zakupki.gov.ru/epz/main/public/document/view.html . Исторический FTP не использовать как действующий канал.
