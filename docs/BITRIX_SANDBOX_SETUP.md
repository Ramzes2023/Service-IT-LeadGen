# Битрикс24: безопасная подготовка тестовой воронки

## Согласование менеджера, 31 октября 2026 года
Используем рабочий портал только в изолированной тестовой воронке. Существующие компании, контакты, сделки и рабочие процессы нельзя изменять или удалять без отдельного согласования.

## Предлагаемая схема
- CRM deals: entityTypeId = 2, категория с точным именем LeadGen AI — Тестирование.
- **Общая категория 0 запрещена**. Потребуется отдельный categoryId больше 0.
- Стадии: Новый сигнал; Проверка данных и дублей; AI-гипотеза; Проверка менеджера; Контакт разрешён / в работе; Передано в продажи; Отказ / неподходящий.
- Дополнительные поля: локальный ID, ИНН как текст, регион, URL/дата/цитата сигнала, предполагаемая услуга, Lead Score, версия правил, AI-статус, следующее действие. Коды полей узнаем через crm.item.fields после настройки.
- Карточка до контакта — лишь кандидат на продажу; вакансия сама по себе не доказывает потребность купить услугу.

## Минимальные права
- Отдельный пользователь с просмотром/созданием/изменением **своих тестовых записей только в этой воронке**. Без удаления и без прав на рабочие направления.
- Входящий вебхук со scope crm, если портал и администратор это позволяют; права пользователя применяются к запросам.
- Лучше, чтобы администратор создал воронку и дополнительные поля по этой схеме. Альтернатива — временное разрешение менять настройки CRM; после настройки обязательно отозвать. Это право шире одной воронки.
- Только после отдельного разрешения — чтение существующих компаний/контактов для проверки дублей.
- Отключить роботов, триггеры и уведомления тестового направления до внесения тестовых данных.

## Что уже есть в коде
Новый модуль leadpilot.bitrix_sandbox выполняет только читающие REST API запросы:
1) crm.category.list: поиск строго нашей воронки, а не соседних.
2) crm.item.fields: перечень полей сделок.
3) crm.status.list: стадии конкретного найденного направления (DEAL_STAGE_<categoryId>).

Никаких методов создания, обновления или удаления. Если тестовая воронка отсутствует или не совпадает ID, операция останавливается. Токен и названия других воронок не выводятся.

### Проверить проект без доступа (офлайн)
    .\.venv\Scripts\python.exe -m leadpilot.bitrix_sandbox --blueprint

### Проверка после разрешения и получения вебхука (только чтение)
Настроить BITRIX24_TEST_WEBHOOK локально в защищённой среде; не отправлять URL в чат или GitHub. Опционально задать BITRIX24_SANDBOX_CATEGORY_ID и BITRIX24_SANDBOX_NAME. Затем:
    .\.venv\Scripts\python.exe -m leadpilot.bitrix_sandbox --preflight

Переход к реальным записям в рабочий портал — отдельный этап с явным разрешением, проверкой прав, подтверждённой схемой и защитой от дублей.
