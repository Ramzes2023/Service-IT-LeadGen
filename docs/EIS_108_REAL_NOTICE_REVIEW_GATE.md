**Основание: журнал Windows 31.10.2026.** Пользователь запустил изолированный пакет EIS Targeted 1C на SHA `7a2a3bfbbc572c9fe0b9da5d42e51a2c1ba23089`: `165 passed in 1.81s`, четыре последовательных HTTPS RSS запроса к официальному zakupki.gov.ru, `PIPELINE_EXIT=0`. Результат:

|---|---:|---:|---:|

| техническая поддержка 1С | 200 | 12 | 0 |
| доработка 1С | 200 | 1 | 0 |
| настройка 1С | 200 | 9 | 0 |

**Всего 108 уникальных официальных извещений, 0 квалифицированных коммерческих лидов, 0 реальных записей в Битрикс24.** Извещения первой поисковой группы охватывают 44-ФЗ (пробная RSS ссылка), но **не подтвержден** регион Москва/МО, размер заказчика по ФНС или его новый B2B-статус. Число 108 нельзя использовать в отчёте Микаилу как число «готовых клиентов». «Сопровождение 1С» в официальной закупке может быть тендерной возможностью для самого ООО «Сервис ИТ», но это отдельный процесс коммерческих торгов.

## Реализован следующий приёмочный этап: evidence review

`leadpilot.eis_108_review` **offline** принимает четыре уже созданных JSON и сводку. Проверяет все четыре отчёта, точные официальные URL извещений и hash signal_id, повторные URL, дату публикации не старше 30 суток, неизменённое отсутствие менеджерских и CRM-разрешений, точный пересчёт новых кандидатов каждой фразы и общий итог.

Выдаёт **новые файлы без перезаписи**:
- `exports/eis_108_review_<timestamp>.json` — полная исследовательская очередь с ожидаемыми полями для ручной проверки.
- `exports/eis_108_review_<timestamp>.csv` — UTF-8 BOM для Excel: URL оригинального извещения, предмет услуги, дата публикации, название покупателя из RSS (**не подтверждено как юридический покупатель**), число профилей появления, отметки об обязательных проверках.

Возможные `ФГБУ`, `ГБУ`, `ГКУ`, `ГУП`, `МУП` и подобные названия помечаются **только как вероятный публичный сектор**. Это не автоматическая правовая классификация. Такие записи нельзя считать подходящими коммерческими покупателями без юридического анализа оригинала.

Ни у одного экземпляра не устанавливаются ИНН покупателя, размер по ФНС, регион, срок подачи, корпоративный контакт, лид-скоринг, право писать или звонить, решение менеджера. Все эти условия остаются явными `verification_holds`, `crm_ready=false`.

## Как использовать после создания CSV

Приоритет — не отправить Микаилу случайные государственные закупки под видом потенциальных клиентов, а выбрать из списка 10–20 наиболее обоснованных **исследовательских** записей, открыть их официальные карточки и установить:
1. конкретного юридического заказчика и **ИНН именно заказчика**, а не поставщика или организатора;
2. статус процедуры и реальный дедлайн;
3. предмет подтверждённой внешней услуги (не только лицензии, не 1С-Битрикс);
4. регион и размер организации по официальному реестру ФНС, микро/малое Москва/МО;
5. наличие официального законного корпоративного канала связи; основания для коммерческого обращения, проверка существующих клиентов/дублей/стоп-листа;
6. письменное решение менеджера о передаче, предварительно только в разрешённую тестовую зону корпоративного Битрикс24.

Для обычного направления государственного тендера по 44-ФЗ следует хранить **отдельный статус тендерной возможности**, а не выдавать за входящий лид малого бизнеса.

### Текущие ограничения

- Нет автоматизированного API для идентификации и точной сверки INN/FNS отдельных покупателей.
- Нет подтверждённых прав и конфигурации для записи в корпоративную CRM, а существующий Bitrix механизм остаётся read-only.
- Ветка не сливается с `main` и не меняет VALYQON.
- Этот этап проверяет только **сохранённые локально исходные JSON**, не делает новых HTTPS запросов и не собирает персональные данные.
- **Новый код ещё не проходил full Windows acceptance**, синтетические тесты добавлены в `tests/test_eis_108_review.py`. Предыдущие 165 PASS относятся к предыдущему коммиту.

После получения сформированного CSV/JSON оператор может прислать файл в проект, чтобы провести предметную проверку конкретных 10–20 извещений, а не только обсуждать численность выдачи.
