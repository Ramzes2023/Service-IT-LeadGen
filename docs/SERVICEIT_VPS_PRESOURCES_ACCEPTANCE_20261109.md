## Что НЕ доказано / намеренно не делалось

1. **Реальный E2E нового источника → новая CRM карточка → RouterAI → 9 полей → Канбан → менеджерская задача → ФНС/МСП → итоговый Score.** Во время аудита после VPS-cutover было 0 новых карточек и 0 квитанций. Это нормальный факт отключённых источников, но **не доказательство полноты бизнес-автоматизации**.
2. Полный корпоративный STOP/проверка действующих клиентов и разрешение маркетингового контакта **НЕ подтверждены**; пользователь выбрал собственный стоп-лист, пока пустой. Видимые CRM совпадения и бесплатный реестр МСП не дают права автоматически звонить и писать.
3. Полный E2E Билайн ОАТС, Telegram/WhatsApp/других ботов, email-домена, SLA manager RBAC и юридического согласия **не подтверждён**. Код postcall зависит от действий менеджера в CRM, не от доказанного прямого подключения АТС. Автоматических исходящих контактов НЕТ.
4. Реальные завершённые звонки и выигранные сделки для бизнес-модулей ещё не наблюдались; нельзя утверждать, что реальная задача/финансовый черновик прошёл readback по живому событию.
5. Резервные копии шифрованно не вывезены на **отдельный сервер/объектное хранилище**; текущие частные копии и восстановление в изолированном PostgreSQL проверены **на том же VPS**.
6. Источники (B2B-Center, Bidzaar, SUPPMAN, вакансии, услуги и др.) не подключены в единый серверный приём; старые GitHub CRM-маршруты теперь запрещены. При следующем этапе потребуются **VPS-совместимые адаптеры каждого выбранного источника**, реальные полномочия доступа, и ограниченный пилот. Это больше, чем просто переключить один общий флаг.
7. Некоторые публичные GitHub вспомогательные расписания сохранены как **непишущий внешний аудит**. GitHub не выполняет production 10-минутный цикл и не должен заменять серверный PostgreSQL.

## Безопасный критерий подключения первого источника

- Один разрешённый источник (не все сразу), низкая скорость, без старого GitHub direct-to-CRM, без автоматического контакта.
- Поступает новая новая CRM HOLD карточка **после VPS cutover** с корректным типом 1062/категорией 21.
- Проверяются на фактической карточке точные 9 AI полей, 3-сигнальное оформление, статус HOLD, отсутствие дубля, задача и версия Score.
- ФНС/МСП проверяется только при корректном ИНН; отсутствие реестра приводит к HOLD, а не к ложному статусу Verified.
- PostgreSQL one-use receipts + Bitrix readback подтверждают одну обработку; старые #3/#7 не изменяются.
- Не открывать исходящий маркетинговый контакт без отдельного решения ответственного менеджера и законного основания.

**Вердикт:** инфраструктура, нативное расписание, модели/браузер, Битрикс-метаданные, защита дублей, изолированное восстановление и внешний мониторинг готовы. *Не* присваивать статус «весь ТЗ реализован и единственное действие — тумблер источников»: телеком/боты/глобальный STOP, прикладной source intake и E2E на реальном потоке требуют отдельной приёмки.
