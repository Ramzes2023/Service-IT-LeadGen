# Сервис ИТ — только AI-анализ и оформление НОВЫХ карточек Битрикс24

Документ уточняет границу задачи Михаила (письмо «ТЗ Лидогенерация» от 30.10.2026, ТЗ 3.0): **не подключать источники закупок, Gmail, финансовый модуль и иные проекты** в рамках этого шага.

## Подтверждено
- Смарт-процесс Bitrix24: entityTypeId=1062, categoryId=21.
- Live read-only: 9 AI-полей + Score/version/badge = 12/12, `SERVICEIT_ALL_12_FIELDS_READONLY_PASS`.
- GigaChat: синтетический тест `GIGACHAT_COCKPIT_PREFLIGHT_PASS` (не означает реальный отчёт по клиенту).
- Из GitHub PR #89 (merged) доступен Windows-планировщик с 5-минутным циклом и SQLite-журналом.
- Карточки №3 и №7 не меняются. Нет доказанного полного E2E с реальной новой карточкой.

## Как система должна работать
1. Найти новое ID>=8 в 1062/21, прочитать карточку без изменения исходных CRM-данных.
2. Если независимые подтверждения отсутствуют, показать 9 достоверных предварительных полей HOLD. **Это не AI-ответ, и Score/цвет должны оставаться пустыми**; без подготовки звонков или выдуманных сведений.
3. Если CRM snapshot, источник, дата, ИНН, ФНС/география, клиент/дубли/стоп-лист, законность контакта и менеджерский допуск подтверждены независимым корпоративным checker + approved privacy, вызвать НАСТОЯЩИЙ GigaChat на очищенном тексте сигнала.
4. Убедиться, что дословная цитата присутствует в исходных данных; AI-confidence только гипотеза. Рассчитать детерминированный Score по формуле, сохранить scoring version и объяснение факторов (правило из ТЗ Михаила).
5. Защищённо записать ровно 9 AI + 3 Score-поля, перечитать CRM и сверить значения. При неопределённом результате не повторять POST вслепую, сначала ручная read-only сверка.
6. В детальной форме отобразить отчёт, доказательства, рекомендацию услуги, следующий шаг; отдельно проверить сохранённый вид канбана под аккаунтом менеджера. Никаких автоматических рекламных действий.

## Включение на Windows (только уполномоченный оператор)
1. После проверки нового PR обновить локальную основную ветку и убедиться, что штатный Python из `.venv` доступен. Команды Git нужно запускать в уже существующем локальном репозитории пользователя, не скачивая неаудированный установщик из интернета.
2. Запустить `scripts/INSTALL_SERVICEIT_ALL_CARD_AUTOFILL.ps1 -ConfigureGigaChat` с утверждёнными корпоративными правами. Отдельно подтвердить возможность автоматической записи 9 предварительных полей и передачу только разрешённых данных модели. Установщик спрашивает **отдельные** секреты Bitrix24 и GigaChat через скрытый ввод, защищает их DPAPI текущего Windows-пользователя. Не копирует ключи из VALYQON/TenderLens или другого проекта.
3. Не добавлять `-ApplyCommonDetailLayout` без отдельного администраторского разрешения, сохранённой общей конфигурации и возможности проверить бэкап/readback. Канбан не является частью этой операции.
4. Проверить задачу `ServiceIT-AI-Autofill-1062-21`, запуск и журнал `%LOCALAPPDATA%\\ServiceIT\\AI-Autofill\\state\\new-card-events.sqlite3`. Планировщик действует только пока пользователь вошёл в Windows.
5. Первый новый **разрешённый** ID>=8 проверить в CRM: до/после, 9 или 12 полей, настоящий GigaChat для полного варианта, правильный Score/version, отсутствие дубля и сохранность остальных полей.
6. Проверить второй цикл без повторной записи. Только после live E2E подтверждать «работает автоматически». Для 24/7 при выключенном ПК нужна отдельно разрешённая постоянно работающая инфраструктура.

**Важно:** Установленный планировщик не является автоматическим корпоративным источником доказательств. Пока внешний checker отсутствует, у новой карточки честный HOLD; модель не должна придумывать уверенность и численную оценку.

## Регрессия / защита
- Не изменять существующие карточки №3 и №7 и их исторические write-ledgers.
- Не изменять смарт-процессные стадии, источники данных, задачи, контакты, STOP-лист, телефонию, автообзвон, существующий Bitrix24 маршрут.
- Не импортировать сторонние GigaChat ключи из чужих проектов или их `.env`.
- Отдельно подтвердить согласие компании на передачу очищенных сигналов модели.
