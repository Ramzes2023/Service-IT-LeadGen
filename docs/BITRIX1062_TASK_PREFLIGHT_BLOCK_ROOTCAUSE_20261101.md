# ServiceIT Bitrix24 — операционная ошибка предзапуска задачи от 01.11.2026

## Что действительно произошло

Владелец запустил уже объединённый в main оператор PR #47 на корпоративном портале. Сначала был получен:

```text
SERVICEIT_AUTO_TASK=BLOCKED_OR_UNCERTAIN;REMOTE_DEMO_TASK_PREFLIGHT_BLOCKED
SERVICEIT_AUTO_SELF_DEMO_TASK=BLOCKED_OR_UNCERTAIN
```

Это означает:

- Метод `profile` и первичная проверка получателя прошли — иначе оператор показал бы ошибку `OWNER_...`.
- Затем `execute_one_demo_task` вызвал `discover_demo_manager_task` и получил неуспех **перед `_ledger(...)` / `_reserve(...)` и `tasks.task.add`**.
- **Этот конкретный запуск не создавал задачу** и не резервировал новую строку в SQLite. Это проверено последовательностью вызовов исходного кода, а не предположением по сообщению.
- Метод предварительной проверки ранее всегда превращал конкретный `TaskDiscoveryBlocked` в общий `REMOTE_DEMO_TASK_PREFLIGHT_BLOCKED`, поэтому прежний журнал **не доказывал**, на какой именно операции чтения возникла проблема.

Позже пользователь случайно вставил в PowerShell текст старых журналов целиком: приглашения `PS C:\...>`, строки `remote:`, проценты Git и `SERVICEIT_...`. PowerShell пытался выполнить эти обычные строки как команды и выдавал `ParserError/CommandNotFoundException`. Это **побочные ошибки копирования**, не новая проблема Bitrix/GitHub. Не копируйте в консоль ни готовые логи, ни `PS ...>` / `>>`.

## Исправление

`leadpilot/bitrix_1062_one_shot_task.py` больше не скрывает известный безопасный код из `TaskDiscoveryBlocked`. Отдельно различаются:
- `REMOTE_PREFLIGHT_EXACT_DEMO_METADATA_NOT_READY`;
- `REMOTE_PREFLIGHT_TASK_LIST_HTTP_400 / ...401 / ...403 / ...429 / ...OTHER`;
- `REMOTE_PREFLIGHT_TASK_LIST_API_ERROR`;
- `REMOTE_PREFLIGHT_TASK_LIST_SCHEMA_CHANGED`, `TASK_TITLE_FILTER_NOT_EXACT`, `TASK_CRM_FILTER_IGNORED`, `TASK_ID_INVALID`, `TASK_PAGINATION_UNVERIFIED` и т.д.

Статусы **жёстко перечислены**, не включают webhook, полный URL, сообщение сервера, имена сотрудников, ИНН и данные реальных задач. Новый тот же набор `REMOTE_PREFLIGHT_...` выводится и через `bitrix_1062_auto_owner_demo_task.py`, но по-прежнему **не инициирует создание**, если чтение не прошло.

Независимый быстрый способ проверить текущий портал **только чтением** без повторной попытки POST:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/RUN_SERVICEIT_ONE_DEMO_TASK_DEDUPE_READONLY.ps1
```

Скрипт запросит текущий webhook скрыто и выполнит проверку существующего №1062/#3 и ограниченный поиск связанных/одноимённых задач. После этого в отчёте появится конкретный `reason_code`.

## Не путать стадии

- `METADATA_READY_TASK_NOT_CREATED` ранее подтверждено пользователем на корпоративном портале.
- Новая блокировка возникла **на дополнительной проверке перед задачей**, а не на экране смарт-процесса.
- Если предварительный поиск блокируется, переписывать webhook-права, заново создавать CRM-карточки или отключать проверку дублей нельзя.
- Текущий `main` содержит только предварительную инфраструктуру/код, не работающий production worker.
- Для завершающего **тестового** запуска нужна успешная read-only проверка, подтверждённый получатель без участия Михаила, локальная durable reservation, одна отправка, точный `tasks.task.get` readback. Создание задачи может вызвать внутреннее уведомление сотруднику — никаких уведомлений реальным клиентам нет.
