# Сервис ИТ — автозаполнение всех новых карточек 1062/21 без VPS

Это **конкретная альтернатива серверу** для владельца, пока корпоративный
HTTPS-приёмник не развёрнут. Планировщик Windows раз в 5 минут выполняет
короткий цикл: REST `crm.item.list` (только ID >=8) → новая карточка
`crm.item.get` → проверка существующих полей → одна допустимая запись
девяти AI-полей → точный `crm.item.get` readback. Работа возможна только при
включённом компьютере и активном пользовательском сеансе Windows.

Все операции проходят через `Store` c отдельной durable SQLite очередью
`%LOCALAPPDATA%\ServiceIT\AI-Autofill\state\new-card-events.sqlite3`.
Перед `crm.item.update` резервируется неизменяемая запись. При неясном
ответе сервера попытка **никогда не повторяется автоматически**; статус
UNCERTAIN должен разобрать оператор по CRM. Схема 12/12 полей проверяется
перед первой допустимой записью; никакие этапы, контакты, клиенты, роботы
или исходные поля не изменяются. Старые карточки #3 и #7 не затрагиваются.

## Режимы

**Каждая новая карточка без независимой проверки:** девять полей с честным
предварительным отчётом. Статус `NOT_RUN_SOURCE_UNVERIFIED`, указаны
ограничения, следующий шаг, чек-лист. **Это НЕ отчёт GigaChat.**
Ни Score, ни цвет, ни правовое основание контакта не выдумываются.
Если карточка уже содержит AI-поля, worker их не перезаписывает.

**Карточка с независимой corporate approval** в файле
`%LOCALAPPDATA%\ServiceIT\AI-Autofill\approvals\<id>.json` и реальной
корпоративно разрешённой моделью: используется существующий универсальный
worker. Он проверяет девять независимых gate, company/FNS, источник,
дубли/клиентов/STOP/legal/contact/manager, before-hash, приватность и
эксклюзивное окно редактирования. Лишь после этого вызывает реальный
GigaChat, рассчитывает Score независимо от confidence, записывает
девять AI + три Score-поля, подтверждает точный readback. Происхождение
approval-документа обязано быть независимым: **нельзя создавать его из
непроверенного source batch, письма B2B или простого значения в CRM**.

Наличие кода не означает подключение такого корпоративного проверяющего.
Пользовательской Windows-установки достаточно для предварительного HOLD,
но **не** для самопроизвольной квалификации источников.

## Установка — одна команда после обновления main

1. Использовать существующую локальную копию `CRM-Readonly-...` с venv.
2. Обновить код `git pull --ff-only origin main` после слияния PR.
3. Запустить `scripts/INSTALL_SERVICEIT_ALL_CARD_AUTOFILL.ps1` с
   `-UseExistingGigaChat -ApplyCommonDetailLayout`, если разрешено использование
   локального GigaChat-ключа и администратор подтвердил изменение общей
   детальной формы для всех пользователей. Этот параметр отдельно запросит
   подтверждение и сохранит полный исходный layout перед изменением.
   При отсутствии прав общую раскладку не менять. Если разрешён перенос локального
   уже проверенного GigaChat-ключа для квалифицированных сигналов.
4. В терминале один раз подтвердить автоматическую запись в **новые**
   карточки, ввести скрытый REST-вебхук. Он сохраняется только
   через Windows DPAPI текущего пользователя. Опциональное согласие
   на передачу сигналов GigaChat спрашивается отдельно.
5. Планировщик `ServiceIT-AI-Autofill-1062-21` создаётся на пять минут.
   По желанию сразу вызвать `RUN_SERVICEIT_ALL_CARD_AUTOFILL.ps1`, чтобы
   увидеть redacted cycle. Невозможность доступа к сети или серверу
   не скрывается под статусом «готово».

После установки видно задачу через Планировщик Windows. Не переносить
DPAPI-файлы на другую учётную запись или сервер. Для постоянной работы
при выключенном ПК нужен корпоративный VPS/HTTPS приёмник.

## Внешние границы

Настройка **канбанной карточки** и **общего layout** не делается этим
фоновой задачей: это отдельная настройка корпоративного интерфейса
Битрикс24. Подготовленный manifest `serviceit_manager_ai_card` только
описывает поля, но не подтверждает, что они видны всем менеджерам.
Для общей раскладки `crm.item.details.configuration.set(scope='C')`
требуются права администратора и точный полный снимок текущей
конфигурации; метод полностью заменяет её, а не добавляет поля.
Не посылать вслепую частичный набор. Kanban display fields в
официальной справке настраиваются через ⚙️ > Настройки канбана >
Настроить карточку просмотра и требуют отдельной проверки сохранения.

**Критерии приёмки**: новая реальная карточка ID>=8 →
HOLD с девятью достоверно сохранёнными полями → повторный цикл
без дубля; отдельно после независимой проверки — подлинный
GigaChat + 12 полей + Score/readback. Настроенный и сохранённый
канбан проверяется независимо.
