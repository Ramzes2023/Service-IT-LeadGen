# Переключение MVP «Сервис ИТ» на прямой спрос: 1CLancer RSS заданий

## Почему этот источник

Оператор **подтвердил на Windows** работу ЕИС, 108 уникальных извещений услуг 1С и 108/108 вероятных публичных покупателей по тексту названия. **ЕИС = канал исследования возможного участия «Сервис ИТ» в закупках, НЕ доказанные B2B-лиды малых коммерческих покупателей Москвы/МО.**

На 31.10.2026 непосредственно на [странице RSS 1CLancer](https://1clancer.ru/rss/) размещена ссылка **«Задания»** на `https://1clancer.ru/i/pics/rss/main.xml`. Сайт сообщает об обновлении RSS-каналов раз в 15 минут. Есть отдельно «Вакансии» — их этот адаптер не принимает. В технической справке сайта [1cl.su/help](https://1cl.su/help/) объясняется, что в разделе «Задания» публикуются **конкретные задачи 1С со сроком выполнения**, а постоянный найм — в «Вакансии». Следовательно, это более прямое доказательство открытого запроса на услугу, чем объявление о найме внутреннего специалиста.

## Что уже реализовано

`leadpilot/oneclancer_rss.py` выполняет **ровно один HTTPS GET** опубликованной XML ленты (нет редиректов, нет отключения TLS/сертификатов, нет логина, private/API обходов), безопасно разбирает RSS/Atom до 2 МБ и 500 элементов и сохраняет только `/task/NNN` с официальных доменов 1clancer.ru/1lancer.ru. Вакансии, форумы, чужие ссылки и старые записи **не попадают** в исследовательский результат. Срок публикации — до 21 дня, дубли — по ID задачи, отчёт изолируется в `exports/`. Из текста убираются очевидные email и номера телефонов.

Поля: официальная публичная карточка, дата, предмет, короткое обезличенное описание, гипотезы о сопровождении, разработке, интеграциях и настройке 1С. **Заявка не означает, что заявитель — компания**: `buyer_inn=null`, `buyer_region=UNVERIFIED`, `buyer_fns_size=UNVERIFIED`, `task_status=UNVERIFIED_OPEN_OR_CLOSED`, `crm_ready=false`, `outbound_authorized=false` и `qualified_lead=false` до отдельной проверки.

CSV для Excel UTF-8 BOM; защита от CSV formula injection и перезаписи предыдущих отчётов. Нет вызовов Битрикс24, отправки письма, подбора контактов и изменения VALYQON.

### Файлы

- `leadpilot/oneclancer_rss.py` — настоящий HTTP/XML адаптер.
- `tests/test_oneclancer_rss.py` — **17 синтетических/локальных** тестов, включая CLI с сохранённым RSS, фильтрацию вакансий, защита от недоверенных ссылок, старые даты, XML XXE, входные HTTP mock и Excel CSV.
- `scripts/RUN_SERVICEIT_1CLANCER_RSS.ps1` — единый операторский тест+один GET+вывод полученных задач.

### Приёмка и оставшиеся обязательные гейты

Локально в изолированной Linux-среде разработчика: **17 passed (0.10s)** на коде до публикации GitHub. **Реальную RSS-ленту не удалось получить из среды разработчика: DNS заблокирован**, поэтому **LIVE_FETCH пока НЕ VERIFIED**. Не выдавать пройденные тесты за проверку живого источника; первый настоящий вызов должен пройти на Windows владельца, где ранее успешно работал EIS RSS.

Настоящая приёмка: `CLANCER_RSS_ACCEPTANCE=PASS` и численное `CLANCER_RESEARCH_TASKS` после живого HTTPS-запроса. Даже тогда **фильтр заказчика обязателен**: открыть саму карточку, убедиться что заказ ещё «Заявка», установить точное юридическое лицо/ИНН (если вообще есть), регион и микро/малое по официальной ФНС, проверить корпоративный канал отклика и согласие менеджера; учесть клиентов/дубли/стоп-листы. Если автор — частное лицо без юридического покупателя, это **заказ на бирже**, но не B2B-лид Микаила.

У B2B-Center отдельная ветка PR #28: нет доказанного метода API поставщика или разрешённой реальной выгрузки. Регламент площадки предполагает права доступа и тариф; **автоматически скрейпить страницы или придумывать API endpoint нельзя**. Когда появится разрешённая выгрузка, действующий `leadpilot.b2b_center_source` позволит сверить ИНН/ФНС. Пока primary goal — получить хотя бы одну открытую реальную заявку по одному из подключённых законных публичных источников и затем доказать её B2B-покупателя.

**Основной репозиторий main и VALYQON не изменены. PR draft до живого теста, Bitrix24 не подключён.**
