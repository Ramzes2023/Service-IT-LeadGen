# Bitrix24: read-only проверка уже созданной задачи по DEMO-ITREQ-001 (01.11.2026)

## Подтвержденная исходная точка

Владелец получил от реального `serviseit.bitrix24.ru`:

```text
METADATA_READY_TASK_NOT_CREATED
methods_ok=4
owner_symbol_verified=true
task_link_enabled=true
automation_confirmed_off=true
task_fields_ready=true
exact_demo_card_readback=true
task_created=false; crm_writes=NO
```

Это подтверждает техническую готовность Bitrix24 и **не подтверждает наличие новой задачи**. Смарт-процесс 1062/21, DEMO #3 сохранен без изменений.

## Новый компонент

`leadpilot/bitrix_1062_task_dedupe_readonly.py` в пределах одного входящего вебхука:

1. Независимо перепроверяет метаданные процесса и всю identity существующей DEMO-карточки #3 через уже протестированный `audit_synthetic_task_link`.
2. Выполняет read-only `tasks.task.list` с точным фильтром `UF_CRM_TASK=T426_3`.
3. Отдельно ищет `TITLE="[DEMO / НЕ ЗВОНИТЬ] Проверить сигнал 1С по карточке ServiceIT №3"` — чтобы найти даже учебную задачу без CRM-привязки.
4. Всегда задаёт `select=[ID,TITLE,RESPONSIBLE_ID,UF_CRM_TASK]`, проверяет формат ответа и точное соответствие фильтру; страницу в 50 записей не принимает за полный результат без корректного курсора. Ограничивает поиск двумя страницами, после чего блокируется, а не объявляет отсутствие дублей.
5. Возвращает **только** найденные ID и итоговые счётчики, без описаний/имён/почты, вебхука, персональных сведений или текстов ошибок от API.

Подтверждаемое состояние:
- `EXISTING_VISIBLE_TASK_FOUND` — по доступному вебхуку уже видна учебная задача; не создавать вторую.
- `NO_VISIBLE_MATCH_NOT_GLOBAL_PROOF` — в данном ограниченном результате задач не найдено. Это **не доказывает** глобальное отсутствие задач, так как API ограничен правами пользователя вебхука. Не является разрешением на POST.
- `BLOCKED_READ_ONLY` — фильтрация, право доступа, пагинация или схема не подтверждены.

Любой результат сохраняет `safe_to_create_task_now=false`, `task_created=false`, `crm_writes=NO`.

## Скрипт Windows

`scripts/RUN_SERVICEIT_ONE_DEMO_TASK_DEDUPE_READONLY.ps1` запускает проверку локально, закрыто запрашивая разрешённый вебхук и очищая его из переменной окружения после завершения. Важно не вставлять вебхук в чат или в GitHub.

Официальные методы:
- [tasks.task.list](https://apidocs.bitrix24.ru/api-reference/tasks/tasks-task-list.html): фильтр `UF_CRM_TASK`, `TITLE`, `select`, постраничная навигация.
- [Как прикрепить задачу к смарт-процессу](https://apidocs.bitrix24.ru/tutorials/tasks/how-to-connect-task-to-spa.html).
- [Поля задач](https://apidocs.bitrix24.ru/api-reference/tasks/fields.html): `UF_CRM_TASK` явно включается в SELECT, возвращается как `ufCrmTask`.

## Последняя граница перед реальной учебной задачей

**Михаил не является автоматически владельцем использованного webhook.** Нужно независимо подтвердить `RESPONSIBLE_ID` через профиль пользователя и корпоративные права. Подготовить безопасную одноразовую постановку с локальным журналом, проверкой дубликатов, отсутствием слепого повтора POST, последующим `tasks.task.get` с `select UF_CRM_TASK`. Создание задачи может инициировать внутреннее уведомление ответственному, даже если текст DEMO; требуется осознанно выбранный исполнитель и разрешение.

**Никакой реальной задачи ещё не создано, ни один клиент не контактировался.** Реальные источники и промышленный worker не активированы.
