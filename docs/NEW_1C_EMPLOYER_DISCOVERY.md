# Новая итерация пилота: искать работодателей 1С и проверять МСП ДО Lead Score

## Почему меняем подход

В первом пилоте из 15 работодателей, найденных по вакансиям 1С, официальная пользовательская выдача ФНС дала 1 малую компанию (отдельная правовая проверка), 3 средние, 1 не субъект МСП и 10 не найденных. Ни одна из них пока не готова к коммерческому контакту. Проблема — обычный поиск вакансий не проверяет размер работодателя.

Это изменение делает **следующую итерацию исследований** воспроизводимой. Источник — официальный API «Работа России», где задокументированы `text`, `offset`, `limit`, региональный поиск. Код делает только один GET на один регион за команду; ограничены `limit <= 50` и индекс страницы `offset` от 0 до 4, без скачивания анкет/HR-контактов. Источник: https://trudvsem.ru/opendata/api (доступность на дату запуска может меняться).

## Этап 1: расширить первую страницу до 50 вакансий (начать с offset 0)

На Windows из ветки нового PR сначала выполните pytest. Затем создайте **новую папку**, чтобы не перезаписывать старые snapshots:

    .\.venv\Scripts\python.exe -m leadpilot.cli --db data/research.sqlite3 source-scan --region 77 --term 1С --limit 50 --offset 0 --output exports/round2_offset0/trudvsem_77.json
    .\.venv\Scripts\python.exe -m leadpilot.cli --db data/research.sqlite3 source-scan --region 50 --term 1С --limit 50 --offset 0 --output exports/round2_offset0/trudvsem_50.json

Эти команды не указывают `--import-to-local`, поэтому лишь сохраняют результаты для предварительной проверки. Если официальный API ответит ошибкой, вывод SOURCE_STATUS=UNAVAILABLE; никаких вакансий не выдавать за найденные. Сначала используйте offset 0 и limit 50: первые 15 ранее уже были изучены, но позиции 16–50 ещё могут содержать новые организации. Если понадобятся следующие результаты, повторите с offset 1 в **новой** папке exports/round2_offset1/ (не перезаписывать снимки offset 0).

## Этап 2: отобрать только НОВЫЕ ИНН и подготовить ФНС

    .\.venv\Scripts\python.exe -m leadpilot.new_1c_fns_precheck --snapshots exports/round2_offset0 --prior-fns exports/fns_official_reconciliation.json --output exports/round2_offset0_precheck.json --inn-list exports/round2_offset0_inns.txt

Модуль проверит 10-значный контрольный ИНН / 12-значный ИНН ИП, официальный URL вакансии, тип 1c_vacancy, дату сигнала (последние 45 дней), регион Москва/МО, повторения по ИНН. **Все 15 уже проверенных ФНС ИНН исключаются** из повторного списка. Если новых кандидатов нет, вернёт NO_NEW_INNS и **не создаст искусственный пустой список**.

Для положительного результата TXT содержит только новые ИНН; скопировать его в официальный поиск https://rmsp.nalog.ru/search.html?mode=inn-list и сохранить Excel и список отсутствующих локально. Для страниц offset0 и offset1 использовать разные --output/--inn-list.

## Этап 3: подтверждение размера до коммерческой квалификации

Только после официальной проверки можно выделять микро/малые организации для углублённой проверки конкретной потребности в поддержке 1С. Сам факт найма штатного программиста 1С **не означает**, что работодатель хочет приобрести внешний IT-аутсорсинг; в карточке необходимо объяснить гипотезу с осторожной формулировкой.

В этом PR НЕ РЕАЛИЗОВАНА автоматическая интеграция новой пачки Excel с системой CRM. Не смешивать новые ИНН с предыдущим ручным review, пока не будет полного отдельного цикла FNS. Новые компании всегда `crm_ready=false`, никакого автоматического скоринга или коммерческого контакта.

## Условия безопасности

- Нет массового парсинга страниц, непубличных API или многогигабайтной выгрузки ФНС.
- Нет экспортирования имён сотрудников, персональных контактов и данных кандидатов.
- Только локальные ignored exports, без перезаписи существующих файлов и без GitHub публикации реальных выгрузок.
- Отсутствуют отправка в Битрикс24, AI-вызовы, уведомления, рекламные сообщения и изменение VALYQON.
- GitHub Actions пока красный до старта runner, issue #7. PR черновой, проверять локально перед merge.

Пользователь подтвердил 124 passed на Windows для начальной версии, но после 136 passed ошибка offset=50 на следующем шаге раскрыла неверную семантику пагинации. Текущая исправленная ветка PR #14 требует повторных тестов. Следующая страница — offset=1.

**Fail-closed:** если хотя бы один из двух региональных файлов отсутствует, повреждён или не соответствует ожидаемой схеме, новый этап выдаёт ошибку и не объявляет «NO_NEW_INNS». Не подменяйте отсутствие данных выводом об отсутствии спроса.
