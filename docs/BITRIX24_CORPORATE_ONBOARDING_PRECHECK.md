# Корпоративный Битрикс24: подготовка к безопасной приёмке без входа в портал

## Что реально известно

31.10.2026 в Gmail владельца обнаружено письмо **«Приглашение в Битрикс24»** на адрес пользователя; корпоративный портал указан как `serviseit.bitrix24.ru`. **Ни переход по персональной ссылке, ни вход, ни выдача прав, ни REST-тесты не выполнялись.** Ссылки вида `...intranet_invite_dialog.php?...&checkword=...` являются индивидуальными приглашениями; **не переносить их в Issue, Git, README, логи или чат**.

Этот документ — **не подтверждение доступа к CRM и не разрешение писать в неё**.

## До первого входа, без корпоративных данных

- Локальный проект независим от внешнего источника и CRM: `START_LAB.ps1` для показа существующей панели; `leadpilot/architecture_demo.py` для синтетического сквозного сценария.
- Схема сущностей: Company/Lead с точным юридическим ИНН; самостоятельный immutable Signal с датами, TTL, ссылкой, provenance; Review/Reason; фиксированный Score/version; канал/стоп; Manager task/outcome/next action; CRM external id/idempotency.
- Демонстрационная очередь: `leadpilot/workflow_ops.py` (durable local SQLite, retry, audit, stop recheck) и `leadpilot/manager_workspace_demo.py` (синтетические задачи, повторное касание, стоп перед событием). ВНИМАНИЕ: это не RBAC, не настоящие контакты и не оператор Bitrix API.
- Тесты `tests/test_workflow_ops.py`, `tests/test_manager_workspace_demo.py`, `tests/test_architecture_demo.py`; запуск через `scripts/RUN_SERVICEIT_ARCHITECTURE_DEMO.ps1`.
- На первом этапе не добавлять webhook в исходники, не собирать реальные контакты компаний и не переносить существующих клиентов в сторонние среды.

## В первый согласованный вход пользователя (только с разрешения руководства)

1. Открыть приглашение **из собственного Gmail**. Никому не пересылать индивидуальную ссылку.
2. Проверить, что портал в интерфейсе действительно **serviseit.bitrix24.ru**; выяснить роль приглашённого сотрудника и доступные CRM-разделы без изменения данных.
3. С согласия администратора проверить, существует ли изолированный тестовый **смарт-процесс** / отдельная воронка `LeadGen AI — Тестирование`, какие ID (`entityTypeId`, `categoryId`, `stageId`) и точные коды custom fields.
4. Узнать, отключены ли у тестового объекта роботы, триггеры и исходящие рассылки. Без письменного подтверждения — никаких тестовых `crm.item.add`.
5. Согласовать минимальный webhook **только на чтение** и хранить его локально в пользовательском окружении (`BITRIX24_TEST_WEBHOOK`), не в GitHub/chat. По метаданным `crm.category.list`, `crm.item.fields` и `crm.item.list` проверить конфигурацию без публикации контактов/списков клиентов.
6. Согласовать правильный метод дедупликации по ИНН в реальных данных, existing clients, стоп-лист и автоматизацию. Право пользователя видеть меню CRM НЕ означает доступ к данным CRM.
7. Только после отдельного разрешения — один синтетический тестовый элемент в изолированной категории с явной меткой `DEMO`, тест idempotency и удаления/архива по согласованной процедуре. Продажных лидов до этого не писать.
