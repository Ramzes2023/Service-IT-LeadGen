# Подтверждённый размер бизнеса → проверка публичных сигналов 1С

Дата подготовки: 31.10.2026. Базовая ветка — PR #16, где владелец на Windows подтвердил **165 passed** и успешный локальный импорт **50 московских микропредприятий** из реального XLSX ФНС: `SME_FIRST_IMPORT=SUCCESS; SIZE_ONLY_RESEARCH=50; CRM_WRITES=NO`.

## Цель следующего этапа

Точно сопоставить **по ИНН** 50 организаций в `exports/sme_first_moscow_50.json` со свежими записями о вакансиях 1С из уже сохранённых и проверенных снимков:

- `exports/round2_offset0/trudvsem_77.json` и `trudvsem_50.json` (страница 0);
- `exports/round2_offset1/trudvsem_77.json` и `trudvsem_50.json` (страница 1).

Проверяются **сам факт вакансии на официальном сайте, ИНН, регион, дата (не старше 45 дней), HTTPS-домен, а также метаданные пагинации**. Повторные URL для одной фирмы объединяются. Названия компаний могут отличаться, поэтому при совпадении по ИНН обязательна проверка идентичности работодателя человеком.

**Ключевое ограничение:** публикация вакансии 1С — признак внутренней потребности в специалисте, а не подтверждённый запрос на внешний аутсорсинг 1С. Нет совпадений в этих двух страницах — НЕ значит, что у компании нет потребности.

## Результат

- `exports/sme_moscow_50_demand_audit.json`: для каждой подтверждённой микро-компании статус, свидетельство, даты и ссылки, без контактов;
- `exports/sme_moscow_50_demand_audit.csv`: короткая рабочая таблица (UTF-8 BOM), безопасные для Excel значения имён;
- `PUBLIC_1C_VACANCY_REVIEW` — найден актуальный публичный сигнал **только для ручной проверки**;
- `NO_MATCH_IN_SAMPLED_VACANCIES` — совпадения **не обнаружены среди сохранённых вакансий**, это не отказ и не вывод об отсутствии спроса.

В любом случае: `lead_score=null`, `crm_ready=false`, `outbound_authorized=false`, `crm_writes=NO`, `outbound_messages=NO`.

## Локальный запуск в Windows PowerShell

Из папки репозитория после переключения на ветку нового PR:

    powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/RUN_SME_VACANCY_AUDIT.ps1

Скрипт ASCII-only для PowerShell 5.1, проверяет правильную ветку, наличие FNS JSON и **всех четырёх** прежних snapshots, запускает все тесты, затем выполняет только offline-аудит и проверяет 50 исходных организаций перед успешным статусом. Если отчёты уже существуют, скрипт намеренно откажется их перезаписывать.

После выполнения ожидается код `SME_VACANCY_AUDIT=SUCCESS`, где `VACANCY_MATCHED` — **наблюдаемое**, а не предсказанное количество компаний с вакансиями. Если совпадений ноль, это не техническая ошибка; следующий источник спроса должен быть независимым (публичные запросы на сопровождение 1С, специализированные B2B-заявки или официальные закупки).

В проекте добавлено **14 новых pytest-сценариев**, ожидаемый итог 179 тестов, **ещё не подтверждено** Windows или CI. Предыдущие 165 тестов подтверждены. CI issue #7 всё ещё требует отдельного устранения.

## Последующие обязательные проверки

Необходимо установить фактический запрос именно на внешнюю услугу, а не предполагать его по отрасли или вакансии. Для любой компании, рассматриваемой для будущего контакта, нужны проверка опубликованного корпоративного канала и правового основания, дубликатов и стоп-листов Битрикс24 в разрешённой тестовой среде, правовых ограничений и согласование действий менеджером. В этом PR таких проверок нет.

Официальные персональные контакты не собирались, реальные локальные FNS/Trudvsem файлы в GitHub не отправлялись; VALYQON и рабочий CRM не менялись.
