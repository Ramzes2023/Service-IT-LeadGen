# B2B-Center: Москва и Московская область — геофильтр до CRM

Дата: 12.11.2026. Статус: code-only; production NOT enabled.

## Scope
Рабочий путь: B2B-Center → Gmail → Apps Script → подписанный VPS PostgreSQL inbox → writer → Битрикс24 1062/21.
Bidzaar, существующие карточки, 300-секундный цикл и правила тематической IT-фильтрации не меняются.

## Правило
- Переменная SERVICEIT_B2B_MOSCOW_ONLY_ENABLED=YES включает геодопуск для НОВЫХ карточек.
- Только независимое чтение оригинальной публичной страницы процедуры, с подтверждением точного B2B-номера, предмета и поля МЕСТА ИСПОЛНЕНИЯ.
- Москва и Московская область — допускаются. Иной субъект, смешанная география и отсутствие доказательства — PG REVIEW, CRM POST запрещён.
- Адрес организатора, регистрация заказчика, регион почтовой подписки, поисковый snippet, LLM, footer страницы — НЕ доказательства места исполнения.
- Поиск географии не расходует Brave/Tavily/RouterAI: только публичный B2B URL и robots.txt с SSRF/HTTPS/robots-ограничениями.
- При 403/401, закрытой странице или отсутствии явного адреса решение UNKNOWN, не выдумывать московский регион.
- Дубли и POST_UNCERTAIN не переотправляются, старые карточки не удаляются.

## Риск запуска
В большинстве подписанных Gmail уведомлений region=null. Если публичная B2B-страница не раскрывает место исполнения, строгий фильтр не создаст московскую карточку даже когда она действительно локальная.
Нельзя включать фильтр вслепую, иначе можно остановить полезные заявки.

## Production acceptance (ещё НЕ выполнялась)
1. Проверить GitHub CI и exact reviewed SHA.
2. На реальном VPS только чтением проверить 1 Москва, 1 Московская область, 1 вне зоны и 1 недоступную страницу.
3. Только если страницы дают точное место исполнения, точечно обновить writer; оставить прежний Docker image и план rollback.
4. Выставить SERVICEIT_B2B_MOSCOW_ONLY_ENABLED=YES; подтвердить 300s цикл, отдельные счётчики geo_unknown, geo_outside, geo_mixed.
5. Подтвердить одну реальную московскую CRM карточку и ноль карточек для non-Moscow/unknown; старые карточки без изменений.
6. При слишком частом UNKNOWN сохранить OFF; дополнить независимыми разрешёнными источниками, не использовать регистрацию заказчика.

Примечание: текущие IT-категории сохраняются. Это фильтр только по географии уже подходящих ServiceIT тендеров, не импорт всех отраслей.
