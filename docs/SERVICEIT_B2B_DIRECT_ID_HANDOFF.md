# «Сервис ИТ»: прямой ID от источника к AI-обработчику

Дата: 2026-11-03. **Опциональный механизм, выключен по умолчанию.**
Это не новая карточка, не новое создание и не автоматический Score.
Предназначено для уже существующего корпоративно разрешённого производителя
B2B-Center → Битрикс24 смарт-процесс 1062/21.

## Исправление архитектуры

Предыдущий бесплатный облачный worker пытался узнать новый CRM ID через
`crm.item.list`, который на реальном портале возвращал неоднозначное `[[]]`.
Это создавало бесконечные диагностические повторы и не гарантировало
обработку данных.

Фактически `b2b_github_to_bitrix.run_once` уже получает **внутренний**
`card_id` после `crm.item.add` и затем читает **именно эту** карточку
через `crm.item.get`. После точного readback опциональный хендлер теперь:
1. Валидирует внутренний ID 1062/21, source ID и реальный status HOLD;
2. Упаковывает только техническую ссылку без имени клиента, ИНН, email,
   темы закупки, URL или персональных данных;
3. Шифрует receipt ключом Fernet из GitHub Secret;
4. Пишет уникальную запись в отдельную ветку
   `serviceit-ai-encrypted-ledger`, каталог `.serviceit/handoffs/`,
   с публичным именем SHA256 вместо реального ID;
5. Возвращает `ENCRYPTED_ID_DELIVERED` только при GitHub 201 с SHA;
6. Следующий потребитель по этому точному source ID расшифровывает номер
   и использует **только** `crm.item.get` для проверки текущей карточки.

Этим устраняется **повторное перечисление списка после успешного создания
карточки**, но не начальная защищённая проверка source duplicate перед
`crm.item.add`; её нельзя отключать без независимого подтверждения.

## Как источник будет запускаться в бесплатном облаке

Добавлен `.github/workflows/serviceit-b2b-direct-id-new-notice.yml`
(по умолчанию job SKIPPED). Он реагирует на **новый подтверждённый
комментарий владельца** с `SERVICEIT_B2B_NOTICE_V1` в Issue #66 и
использует общую с однокарточным пилотом блокировку `concurrency`.
GitHub Actions выполняет Python вне Windows. Публичные комментарии нельзя
использовать для конфиденциальных сведений клиентов; notice schema
сознательно ограничивает передаваемые поля. Сам факт запуска от Issue
пока зависит от появления нового разрешённого review-события; Gmail
автоматически не превращается в такой комментарий.

Активация возможна только при добровольно заданном
`SERVICEIT_B2B_DIRECT_AUTO_ENABLED=YES`, доступном корпоративном
вебхуке в GitHub Secrets, подтверждённой политике хранения
зашифрованного ID и отдельном `SERVICEIT_DIRECT_ID_HANDOFF_ENABLED=YES`
при наличии ключа `SERVICEIT_GH_LEDGER_KEY`. GigaChat остаётся OFF,
если отсутствуют отдельные разрешения
`SERVICEIT_B2B_GIGACHAT_AUTO_ENABLED=YES` и
`SERVICEIT_B2B_GIGACHAT_PRIVACY_APPROVED=YES`, а также секрет/согласованные
условия API. Платные услуги не запускаются.

**Важно:** до нового owner opt-in, корректного dedup preflight и
сквозной проверки нельзя считать этот workflow работающим в production.
Чтение `crm.item.list` для предотвращения дублей **перед созданием**
в базовой реализации ещё есть и может возвращать неоднозначное
`[[]]`; хенд-офф устраняет только повторное сканирование после создания.
Следующая безопасная доработка — источник-специфичная проверка дублей
без непроверенного обхода CRM.

## Безопасность и ограничения

- Триггер: `SERVICEIT_DIRECT_ID_HANDOFF_ENABLED=YES` **только при**
  наличии `SERVICEIT_GH_LEDGER_KEY` и разрешённого GitHub token contents
  write. В существующем одном B2B пилоте флаг пока **не установлен**,
  разрешение `contents: read`; поэтому работающие карточки не затронуты.
- Если GitHub подтвердил существование receipt, никакого overwrite/retry.
  Если запись после CRM create недостоверна, источник остаётся созданным,
  результат `UNCONFIRMED_DO_NOT_RETRY`. Нельзя повторно создавать карточку.
- `crm.item.get` при проверке receipt только READ, никаких
  `crm.item.update`, `crm.item.list`, звонков, SMS, писем.
- Данные клиента в публичную ветку не помещаются; шифрованный файл и
  хешированный filename видны всем. Требуется сохранность ключа, отдельное
  разрешение на публикацию даже зашифрованного технического ID.
- Импорт уже существующей B2B-Center №4665948 **не выполняется**. Исходная
  карточка остаётся HOLD; старый #7 был удалён владельцем и не ищется.
- Для новых B2B HOLD источник заранее записывает в девять AI-полей
  правдивый шаблон предварительного разбора. **GigaChat при
  `SERVICEIT_B2B_GIGACHAT_AUTO_ENABLED=NO` не запускается.**
  Разрешённый GigaChat на ТЕМЕ письма можно отдельно включить в
  существующем `run_once` при корпоративной privacy approval, API-ключе
  и расходном лимите. Его результат только гипотеза, не квалификация.
- Настоящий Lead Score по требованиям менеджера возможен **только после
  девяти независимых проверок**, включая первоисточник, ИНН/ФНС, регион,
  дубли, стоп-лист и юридическое право контакта. Эти внешние верификаторы
  отсутствуют; выдавать 90/100 по неподтверждённому HOLD нельзя.
- Эта PR **не включает** по расписанию GitHub Actions, не вызывает
  реальный API и не переключает `-Apply`. Полноценная безручная обработка
  и реальный E2E **пока не доказаны**.
