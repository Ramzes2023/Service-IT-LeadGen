# Сервис ИТ — LeadGen Lab v0.3

Bidzaar supplier API: **LIVE_SOURCE=BLOCKED_NOT_CONNECTED**, реальных заявок и
квалифицированных лидов — **0**. Подготовлен только ограниченный локальный импорт
разрешённого экспорта, без сети и CRM-записей. Buyer Connector API не заменяет
supplier feed. [Отчёт и блокеры](docs/BIDZAAR_SUPPLIER_SOURCE_ACCEPTANCE_20261031.md),
[контракт и CLI](docs/BIDZAAR_NORMALIZATION_CONTRACT.md).

> **Статус:** проверенный локальными тестами прототип. Никаких реальных CRM-записей, звонков или исходящих сообщений. Реальное подключение внешних API выполняется **только на явную команду**.

## Важно: это надстройка над Битрикс24, а не замена CRM

Целевая цепочка по ТЗ:

`Разрешённый источник → сигнал с URL и датой → проверка компании и ИНН → стоп-лист / дубли → AI-гипотеза (проверяется человеком) → фиксированный Lead Score → CRM Битрикс24 → задача менеджеру → аналитика и подтверждённые финансовые данные`.

**Состояние v0.3:** первый адаптер официально документированного API вакансий «Работа России», базовая запись сигналов, демо-dashboard, обработчик GigaChat с возможностью смены провайдера, безопасная **только читающая** проверка test-Битрикс24 и генерация примера payload. Полной двусторонней CRM-интеграции и телефонного канала пока нет.

## Windows PowerShell

Используется **уже установленный** Python 3.12. Никакой установки Python и изменений VALYQON.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\START_LAB.ps1
```

Откройте `http://127.0.0.1:8766`. Для остановки — `Ctrl+C`.

После первого запуска можно останавливать сервер и отдельно исполнять команды. В новой консоли:

```powershell
cd "$HOME\Service-IT-LeadGen"  # после распаковки и публикации
powershell -NoProfile -ExecutionPolicy Bypass -File .\SCAN_PUBLIC_VACANCIES.ps1 -Region 77 -Term '1С' -Limit 15
```

Это **один ограниченный реальный GET** к официально документированному API `https://opendata.trudvsem.ru/api/v1/vacancies/region/77`. Он сохраняет результат только в `exports/trudvsem_probe.json`, но **не создаёт ни одного лида**, пока не передан флаг `-ImportToResearchDB`. Если сервис недоступен, команда сообщает об этом и не подменяет реальные данные синтетическими.

Чтобы проверить Москву и область, повторите с регионами `77` и `50`; для Ингушетии — `06` (второй приоритет ТЗ). Термины: `1С`, `системный администратор`, `IT-инженер`.

### Отдельная исследовательская БД (только после проверки источника и условий использования)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\SCAN_PUBLIC_VACANCIES.ps1 -Region 77 -Term '1С' -Limit 15 -ImportToResearchDB
```

**Важные свойства:** API не используется для сбора телефонов или личных контактов; если ИНН отсутствует, запись помещается в `source_candidates` для проверки, а не превращается в вымышленный лид. Источники и даты сохраняются. Это всего лишь **возможный сигнал потребности**, а не доказательство намерения купить.

Для просмотра полученных данных отдельно от демо:

```powershell
$env:LEADPILOT_DB = Join-Path (Get-Location) 'data\research.sqlite3'
.\.venv\Scripts\python.exe -m leadpilot.cli report
.\.venv\Scripts\python.exe -m leadpilot.cli source-candidates
```

Чтобы увидеть исследовательскую БД в веб-панели, запустите отдельный сервер на другом порту:

```powershell
$env:LEADPILOT_DB = Join-Path (Get-Location) 'data\research.sqlite3'
.\.venv\Scripts\python.exe -m uvicorn leadpilot.web:app --host 127.0.0.1 --port 8767
```

В браузере — `http://127.0.0.1:8767`.

### GigaChat — только с отдельной оболочкой и разрешёнными данными

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\RUN_AI_FROM_VALYQON.ps1 -Max 2
```

Скрипт **только читает** известные локальные файлы конфигурации для получения ключа GigaChat и передаёт его в окружение отдельного процесса. Не изменяет VALYQON. Если `.env` нет, можно указать `-ValyqonEnvPath` или задать `GIGACHAT_CREDENTIALS` в локальной PowerShell-сессии самостоятельно. Не отправляйте ключи в чат. **Личные квоты GigaChat могут быть общими с VALYQON**, поэтому запуск ограничен двумя запросами по умолчанию.

Реальные публичные сигналы можно отправить на AI-анализ только по отдельному согласию:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\RUN_AI_FROM_VALYQON.ps1 -Max 2 -IncludePublicVacancies
```

При этом передаётся только название вакансии и тип сигнала — **не передаются организация, ИНН, телефон, email или URL**. Содержимое всё равно поступает внешнему AI-провайдеру. Результат помечается `AI_hypothesis`, **не увеличивает Lead Score** и не отправляет коммуникаций клиентам.

### Битрикс24 — проверка на чтение

Пока работодатель не выдал отдельный тестовый портал и разрешённый вебхук, **реальное подключение отсутствует**. Наш `bitrix.py` создаёт только JSON для примера. Когда будет тестовая учётная запись, локально установите переменную окружения `BITRIX24_TEST_WEBHOOK` (не пишите токен в чате), затем:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\CRM_READONLY_CHECK.ps1
```

Команда вызывает только `crm.settings.mode.get` и `crm.item.fields`, ничего не создаёт, не обновляет, не удаляет. Специальный публичный порт, URL пользователя и секрет в выводе не показываются. Текущая реализация поддерживает официальные домены `*.bitrix24.ru`, `*.bitrix24.com`, `*.bitrix24.kz`, `*.bitrix24.by`.
