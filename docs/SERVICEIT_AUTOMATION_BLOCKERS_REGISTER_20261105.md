## Автоматические правила, которые сохраняются

**Рабочий штатный webhook** остаётся неадминистраторским. Никогда не подменять его временным admin-секретом. **Техническая поддержка**, исторические #3/#7, чужие сделки, другие воронки, клиентские переписки, реальные выплаты и источники не меняются. Отчёты и GitHub Step Summary не содержат имен клиентов, ИНН, идентификаторов конкретных новых карточек и финансовых сумм.

### Критерий «полная автоматизация готова»

Нужно на *одной настоящей новой карточке* 1062/21 увидеть чтение после AI 9 полей, task.add/get, безопасный Score, видимость в Канбане менеджера; затем на *реальном подтверждённом звонке* — менеджерский intent, следующее действие и связь с отдельной коммерческой сделкой; на *реальной оплаченной продаже* — сверенный РВП и подписанный финансовый расчёт. Неподтверждённые события не выдавать за нулевые показатели или за успешный запуск.

## Уточнение по финансовой схеме от владельца проекта (05.11.2026)

Владелец прямо сообщил: **компания уже согласовала ставки 15% ему как разработчику, 10% продавшему менеджеру, 75% компании от остатка после прямых расходов.** Не обозначать само согласование этих процентов как открытый корпоративный блокер и не требовать повторной переписки с Михаилом ради утверждения тех же ставок.

Отдельно: это сообщение фиксирует заявленную договорённость, но не создаёт новых банковских документов и не удостоверяет статус payroll-подписанта. Код может считать **предварительные суммы автоматически** по согласованным ставкам; проведение официальных начислений/денежные выплаты требует фактических данных об оплатах, расходах, ответственном продавце и подтверждённого платёжного регламента компании. Не блокировать обычный расчёт одной только необходимостью повторно согласовать проценты.

## Решение владельца: бесплатный ФНС-MVP (05.11.2026)

Платный промышленный ЕГРЮЛ/ЕГРИП **исключён из обязательных интеграций MVP**. Для AI-предварительного анализа, CRM-карточек 1062/21, внутренних задач менеджеров и предварительного ранга НЕ требуется оплата регистрационных API. Бесплатный реестр МСП проверяется отдельным облачным конвейером PR #196 (по новым корректным ИНН); официальный паспорт — PR #197. Реальный запуск 42073746260 подтвердил работу без новых карточек и без загрузки ZIP, но пока НЕ доказал сопоставление в реальном ZIP для нового ИНН.

Для выбранных перспективных компаний менеджер отдельно проверяет юридический статус бесплатной официальной выпиской ЕГРЮЛ/ЕГРИП: https://egrul.nalog.ru/ . Сам факт МСП/корректной контрольной суммы ИНН не доказывает действующий статус, отсутствие дублей, допустимость контакта и наличие спроса. Не автоматизировать веб-форму с обходом защит; не объявлять проверку ЕГРЮЛ выполненной по одному МСП.

Исправления в PR данного этапа: watcher сохраняет в оперативной памяти GitHub token для **чтения собственных зашифрованных МСП-квитанций** (не публикуя секрет), Score отклоняет компании из включённого корпоративного INN STOP, и задача менеджеру прямо указывает бесплатный путь ЕГРЮЛ. Без утверждённого списка STOP не выдавать глобальное CLEAR, а предварительный Score допускается только как гипотеза без разрешения контакта. Новые источники не подключать.
