# Подключение RouterAI к новым карточкам Сервис ИТ

Сервис из сообщения WhatsApp: routerai.ru, базовый URL https://routerai.ru/api/v1. Ранее упомянутый DeepSeek является моделью через маршрутизатор, а не прямым адресом API.

Провайдер конфигурации: routerai. Модель: deepseek/deepseek-v4.1-flash. Адрес запросов: https://routerai.ru/api/v1/chat/completions. Резервный вариант: gigachat.

Ключ, отправленный на скриншоте WhatsApp, раскрыт — его необходимо отозвать в кабинете RouterAI и выпустить новый. Никогда не публиковать его в Issue, коммитах и чате.

Владелец GitHub один раз добавляет новый ключ в Settings > Secrets and variables > Actions: секрет SERVICEIT_ROUTERAI_API_KEY. После решения руководителя о разрешённой передаче корпоративных данных RouterAI: переменная SERVICEIT_ROUTERAI_PRIVACY_APPROVED со значением YES_1062_21. Затем переменная SERVICEIT_AI_PROVIDER = routerai.

Для возврата: SERVICEIT_AI_PROVIDER = gigachat. При отсутствии переменной выбирается GigaChat. Новая интеграция не меняет уже обработанные карточки, фактический Score, проверки ФНС и CRM-дублей, Kanban или текущую воронку техподдержки.

Без нового действительного ключа и отдельного разрешения реальный RouterAI API тест и переключение запрещены. Покупка ключа не равна разрешению передачи внутренних данных.

Базовый AI-режим отправляет ограниченный текст публичного заголовка только после проверки домена источника и разрешения. Для внутренних документов/CRM данных требуются корпоративные approvals. Модель возвращает гипотезу, цитату и направление услуги, а не подтверждённый лид или конечный Lead Score.

Справка: https://routerai.ru/docs/guides/overview/quickstart ; https://routerai.ru/models/deepseek/deepseek-v4.1-flash

## Реальная проверка 04.11.2026 и новая защита от поломки

Новый ключ (значение скрыто) обнаружен GitHub Actions; переменные `SERVICEIT_AI_PROVIDER=routerai` и `SERVICEIT_ROUTERAI_PRIVACY_APPROVED=YES_1062_21` были сохранены владельцем. Публичный тест без данных клиентов:
- #41918392498: отказ `401/403` при платном запросе.
- #41918947336: каталог моделей `GET /models` HTTP 200, но `POST /chat/completions` HTTP 401.
- #41919599689: статус `ROUTERAI_CHAT_401_WITH_CREDITS_UNVERIFIED`. Баланс программно подтвердить не удалось. **Не утверждать, что денег нет или ключ неправильный**.

**Безопасность продакшена:** новый переключатель `SERVICEIT_ROUTERAI_LIVE_READY` должен быть точно `YES_API_CHECK_PASSED`; если отсутствует или иначе настроен, оба основных облачных workflow временно выбирают GigaChat и сохраняют его отдельный TLS CA сертификат, даже если `SERVICEIT_AI_PROVIDER=routerai`. Это предотвращает отказ обработки новых карточек при неисправном платном API. Настройку READY можно устанавливать только после повторного успешного синтетического API теста `ROUTERAI_API_AND_AI_VALIDATION_PASS` под действительным ключом.

Что нужно сделать владельцу аккаунта RouterAI: открыть Биллинг, проверить положительный остаток и лимиты ключа на платные запросы, проверить разрешённость модели. Если аккаунт пополнен, а `POST /chat/completions` возвращает 401 при рабочем `GET /models`, обратиться в поддержку RouterAI с датой и кодом 401 **без передачи API ключа**. После устранения проблемы повторить проверку; только потом добавить переменную `SERVICEIT_ROUTERAI_LIVE_READY=YES_API_CHECK_PASSED`. Не ставить её сейчас.

GitHub Secrets не нужно переписывать без подтверждённой причины. Изменения не затрагивают исторические CRM карточки, Score, источники и менеджерские задачи.
