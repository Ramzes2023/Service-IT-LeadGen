# ЕИС: диагностика реального HTTP/TLS подключения

Скрипт `leadpilot.eis_rss` **не обходит защиту ЕИС**, не делает повторных запросов и не отключает проверку TLS. При любой ошибке выводит только безопасный код без URL и тела ответа.

| Код в консоли | Что означает | Что проверить |
|---|---|---|
| `EIS_SOURCE_UNAVAILABLE_OR_REDIRECT_HTTP_3xx` | Официальный RSS сделал redirect | Реальную RSS-ссылку из интерфейса ЕИС, адрес не менять автоматически |
| `EIS_HTTP_AUTH_OR_FORBIDDEN_403` | ЕИС отказал в доступе | Открывается ли ЕИС вручную в том же браузере, нужна ли авторизация, разрешён ли RSS; обход защит не использовать |
| `EIS_HTTP_RATE_LIMIT_429` | Ограничение частоты | Прекратить автоматические повторные попытки, соблюдать правила источника |
| `EIS_NETWORK_TIMEOUT` | Истёк таймаут сети | DNS, соединение, блокировка маршрута, затем повторить только при стабильной связи |
| `EIS_TLS_TRUST_FAILED` | Python не доверяет сертификату | Использовать только проверенную цепочку доверия из официальной инструкции, `--ca-bundle` при согласованной настройке |
| `EIS_NETWORK_CONNECTION_FAILED` | DNS/порт/доступность и прочие сбои связи | Проверить сеть или передать разрешённую оригинальную сохранённую RSS |
| `EIS_RESPONSE_NOT_XML` | ЕИС вернула HTML, страницу входа или challenge | Не принимать HTML за отсутствие тендеров; исправлять путь доступа согласно правилам ЕИС |
| `EIS_HTTP_STATUS_5xx` | Ошибка источника | Проверить доступность официального портала позже |

**Нельзя** выводить `EIS_STATUS=OFFICIAL_FEED_PARSED` или `QUALIFIED_LEADS>0`, пока исходный RSS и конкретные извещения не проверены. Даже успешный RSS не подтверждает, что заказчики относятся к малому бизнесу Москвы/МО: это отдельная проверка оригинального извещения и официальной ФНС.

Проверка локального механизма: `python -m pytest -q tests/test_eis_rss.py tests/test_eis_real_format.py tests/test_eis_transport_diagnostics.py` — локально **45 passed** (35 существовавших + 10 диагностических тестов). Это не проверка живой сети, Bitrix24 и полного проекта.
