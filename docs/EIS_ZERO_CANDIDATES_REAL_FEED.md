## Новый этап: показать причину нуля

`leadpilot.eis_source_diagnostics` только читает сохранённый отчёт (без HTTPS/CRM) и различает:

- `OFFICIAL_RSS_HAS_ZERO_ITEMS` — официальная RSS вернула 0 записей;
- `ALL_ITEMS_FAILED_EXPLICIT_EXTERNAL_1C_SCOPE` — записи есть, но предмет закупки не подтверждает внешнюю поддержку 1С;
- `ALL_ITEMS_OUTSIDE_30_DAY_WINDOW` — записи слишком старые;
- `ALL_ITEMS_FAILED_NOTICE_URL_VALIDATION` — ссылки на извещения в неподдерживаемом официальном формате;
- `ZERO_AFTER_MULTIPLE_RESEARCH_GATES` — несколько причин вместе;
- `RESEARCH_ITEMS_FOUND_BUYER_STILL_UNVERIFIED` — есть исследовательские кандидаты, но покупатель не проверен.

Чтобы прочитать старый JSON без обновления кода, можно запустить PowerShell:

```powershell
$f = Get-ChildItem "$env:LOCALAPPDATA\ServiceIT\EIS-Acceptance" -Recurse -Filter 'eis_source_*.json' -File |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
if (-not $f) { throw 'EIS_RESEARCH_JSON_NOT_FOUND' }
$doc = Get-Content -LiteralPath $f.FullName -Raw -Encoding UTF8 | ConvertFrom-Json
Write-Output ('EIS_RESEARCH_FILE=' + $f.FullName)
Write-Output ('EIS_ITEMS_COUNT=' + @($doc.items).Count)
$doc.counts | ConvertTo-Json -Depth 5
```

Нужно узнать только **счётчики**, не передавать логины, cookie, приватные токены, персональные данные или HTML из кабинета.

В обновлённой ветке `scripts/RUN_SERVICEIT_EIS_PIPELINE.ps1` после официального парсера автоматически выполняет `python -m leadpilot.eis_source_diagnostics --report...`.

## Что делать после диагностики

1. Если RSS пуста, открыть официальный расширенный поиск ЕИС, настроить точный предмет `сопровождение 1С` и регионы Москва/МО, выбрать нужные законы 44/223-ФЗ и **скопировать настоящую RSS-ссылку из интерфейса ЕИС**. Не придумывать query params.
2. Если записи отсекает фильтр 1С, проверить сохранённые XML/оригинальные ссылки на реальные предметы услуг и расширять `SERVICE_WORDS` только по подтверждённым примерам. Нельзя превращать обычные лицензии или 1С-Битрикс в запрос на аутсорсинг.
3. Если записи устарели, принимать только свежие, пока срок подачи открыт; не переименовывать исторические контракты в готовые лиды.
4. Даже после получения извещений проверить **юридический ИНН именно покупателя** и размер по ФНС. Госпредприятия и крупные заказчики не входят автоматически в пилот малого B2B. Для допуска к CRM дополнительно нужны проверка дублей, действующих клиентов, разрешённого канала, менеджерское согласование и отдельная тестовая зона Битрикс24.

**Подтверждено:** работает доступ к RSS. **Не подтверждено:** подходящие покупатели, обращения, реальные продажи, подготовка и отправка CRM-лидов. Это разные критерии готовности.

## Дополнительная квалификация 200 отвергнутых записей

Первый вывод на Windows действительно: `items_seen=200`, `not_explicit_external_1c_service=200`. Этот единый счётчик ничего не говорит о фактических предметах закупки, потому что программа не сохраняла отказанные записи. В обновлённом `leadpilot.eis_rss` **не ослаблена** проверка целевого предмета: добавлены детализация и максимум 15 образцов публичных названий закупок (по 3 на причину), чтобы можно было обнаружить и исправить именно неверный разбор XML, а не выдавать ложные лиды.

Новые причины:

- `scope_subject_label_missing`: RSS-заголовок вида «Электронный аукцион №…» и нет распознанного поля предмета. Подозрение на отличающийся HTML-шаблон или действительно пустое поле.
- `scope_subject_empty`: распознан пустой или `null` предмет.
- `scope_no_1c_in_purchase_subject`: реальный предмет **не содержит 1С**, хотя строка поиска ЕИС могла содержать 1С.
- `scope_no_external_service_in_purchase_subject`: предмет содержит 1С, но **нет явного сопровождения, поддержки, настройки, доработки и т.п.**; возможно только лицензии, продажа ПО или неоднозначный запрос.
- `scope_bitrix_out_of_scope`: закупка 1С-Битрикс, не целевая поддержка 1С:Предприятие.
- `scope_service_negated`: явно говорится об отсутствии внешней услуги.

**Внимание:** при некорректно распознанном предметном поле перечисленные результаты сами могут ошибаться. Сохранённые образцы — *подсказка для ручного открытия оригинала*, не коммерческое доказательство и не лид.

Скрипт `scripts/RUN_SERVICEIT_EIS_SCOPE_PROBE.ps1` читает JSON первого живого прогона, использует его **раньше применённую пробную RSS-ссылку**, делает **один** новый официальный HTTPS-запрос и показывает подробные причины и до восьми первых образцов. По желанию можно передать `-RssUrl` с настоящей ссылкой, скопированной кнопкой RSS в интерфейсе ЕИС. Самостоятельной генерации поисковых параметров нет. CRM, рассылки, контакты и изменение основного репозитория запрещены.
