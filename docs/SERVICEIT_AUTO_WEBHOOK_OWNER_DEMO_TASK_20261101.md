## Новое: ID ответственного вводить больше не нужно

Официальный Bitrix24 метод `profile` возвращает текущего пользователя из того же REST вебхука; не требует нового scope:
https://apidocs.bitrix24.ru/api-reference/common/users/profile.html

`leadpilot/bitrix_1062_auto_owner_demo_task.py`:
1. Выполняет `profile` по уже разрешённому webhook.
2. **Сверяет ID пользователя из profile c ID самого webhook URL**. Не использует произвольного пользователя и не делает поиска по сотрудникам.
3. Если отображаемые имя/фамилия отсутствуют или похожи на **Михаил / Микаил / Mikhail / Michael**, блокирует операцию, чтобы не уведомлять Михаила вопреки требованию владельца проекта. Личное имя не пишется в лог.
4. Назначает учебную задачу лишь **владельцу текущего вебхука** с явно DEMO-заголовком и запретом реального контакта. Это может создать **внутреннее уведомление этому владельцу**. Он не обязательно совпадает с человеком за Windows-компьютером: при сомнении надо использовать вебхук своего технического аккаунта, а не чужого менеджера.
5. Повторно проверяет точную DEMO-карточку №3, совместимость задач, ограниченный read-only поиск дублей, затем использует **тот же** долговечный `one-demo-task.sqlite3`, что и прежний оператор. В нём сначала устанавливается локальный запрет на повторную отправку, затем допускается один POST `tasks.task.add` и readback `tasks.task.get`.
6. Нет звонков, сообщений клиентам, CRM-записей или новых источников.

Windows-команда после проверенного CI:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/RUN_SERVICEIT_AUTO_OWNER_ONE_DEMO_TASK.ps1
```

Скрипт запрашивает **только секрет вебхука локально скрытым вводом**. ID Михаила и других сотрудников вводить не требуется. Профиль владельца проверяется через REST автоматически.

**Ограничение:** если вебхук принадлежит другому реальному сотруднику, этот сотрудник может получить уведомление о тестовой задаче. Даже при отсутствии Михаила в имени нельзя автоматически доказать, что он не пользуется чужой учётной записью. Поэтому этот оператор предназначен для существующего разрешённого *технического* webhook владельца проекта.

**Статус:** CI и live execution отдельные. До ответа `SERVICEIT_AUTO_TASK=VERIFIED` нельзя утверждать, что задача создана. При любом `BLOCKED_OR_UNCERTAIN` не повторять без проверки локального журнала и `tasks.task.get`.
