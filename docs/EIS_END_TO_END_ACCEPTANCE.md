# ЕИС → менеджер «Сервис ИТ» → Битрикс24: текущее состояние и приёмка

## Что реально построено

Схема по письму Микаила от 30.10.2026: **малые предприятия Москвы/Московской области → свежая внешняя потребность в услугах 1С → обоснование → менеджер → проверка CRM → последующая продажа**.

На стадии кода:

1. `leadpilot.eis_rss` — одиночный HTTPS GET официальной RSS ЕИС, фильтрация реального предмета услуги 1С (не по строке поиска), ссылка, публикация, защита от дублей и исследовательский JSON.
2. `leadpilot.eis_buyer_review` — сверка вручную проверенных на оригинальной странице ИНН **покупателей** с подтверждённой выборкой малых организаций ФНС, статусом закупки, сроком и регионом; без ложного CRM-одобрения.
3. `leadpilot.eis_manager_queue` — один покупатель = одна исследовательская карточка с одним или несколькими извещениями, ссылкой/датой/ИНН/потребностью/ограничениями. CSV + JSON под `exports/`, без дублирования и перезаписи.
4. `leadpilot.eis_bitrix_sandbox` — **только читающая** проверка отдельного смарт-процесса Bitrix24 (entityTypeId >=128, согласованная тестовая категория >0, настроенное поле ИНН). Обычные Leads и Deals этим инструментом не создаются. Результаты CRM-данных не выводятся в логи.
5. `scripts/RUN_SERVICEIT_EIS_PIPELINE.ps1` — последовательный однокомандный прогон тестов, чтения официальной RSS и, при наличии исходных операторских доказательств, исследования покупателя и очереди менеджера.

Это **пока не отправщик рабочих лидов**: пока отсутствуют живой подтверждённый RSS-ответ, подтверждённые текущие сделки небольших организаций, доступ к корпоративной CRM, согласованные юридические/организационные правила обращения. Готовые лиды на текущий момент — **0 подтверждённых**.

## Как запустить на Windows владельца

После обновления тестовой ветки и установки зависимостей из `requirements.txt`, из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\RUN_SERVICEIT_EIS_PIPELINE.ps1 -RssUrl 'РЕАЛЬНАЯ_ССЫЛКА_RSS_СОХРАНЁННАЯ_В_ЕИС'
```

Если официальный HTTPS не доверен системному корневому сертификату, допускается дополнительно `-CaBundle 'C:\path\verified-official-ca.pem'` **только после проверки официального происхождения сертификата**. Нельзя отключать TLS-проверку, использовать фальшивый feed или обходить защиту.

При первой успешной реальной выгрузке будет только `exports/eis_source_<timestamp>.json` и число исследовательских сигналов. **Не равняется готовым лидам.** Следующая стадия требует фактов о юридическом лице и размере из ФНС.

После проверки вручную каждого исходного извещения и его даты, срока, ИНН покупателя:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\RUN_SERVICEIT_EIS_PIPELINE.ps1 -RssUrl 'РЕАЛЬНАЯ_ССЫЛКА_RSS_ИЗ_ЕИС' -FnsFile 'exports\sme_first_moscow_50.json' -BuyerFacts 'exports\eis_operator_facts.json'
```

Формат `eis_operator_facts.json` описан в `docs/EIS_BUYER_FNS_REVIEW_GATE.md`; создавать **только по реальным источникам**, без выдуманных ИНН и дат. При успехе: `exports/eis_manager_queue_<timestamp>.json` и `.csv`. Оператор может вручную передать карточки менеджеру для рассмотрения. Автоматическая рассылка и запись в живую CRM остаются отключены.

## Доступ к корпоративному Битрикс24

Официальная документация требует для новой интеграции универсальные методы `crm.item.*` (не устаревающие `crm.lead.*`). Документы: https://apidocs.bitrix24.ru/api-reference/crm/leads/ ; https://apidocs.bitrix24.ru/api-reference/crm/universal/crm-item-list.html ; https://apidocs.bitrix24.ru/api-reference/crm/universal/crm-item-add.html .

**Особенно важно:** в Битрикс24 категория сделки не изолирует обычные Leads; `crm.item.add` при записи может запускать роботов. Требуется решение CRM-администратора, отдельный тестовый смарт-процесс или проверенная изоляция с правами, запрет рабочих роботов, поля ИНН/источника/даты, политика стоп-листа и проверки существующих клиентов.

Без разрешённого тестового портала модуль `eis_bitrix_sandbox` не выполняет никаких запросов и не подменяет результаты. Если доступ дан оператору локально (никогда не передавать webhook в чат и GitHub), можно выполнить **только read-only**:

```powershell
$env:BITRIX24_TEST_WEBHOOK = '<локально выданный тестовый вебхук>'
.\.venv\Scripts\python.exe -m leadpilot.eis_bitrix_sandbox --entity-type-id 164 --category-id 8 --category-name 'LeadGen AI — Тестирование' --buyer-inn-field 'ufCrm164_123456789'
```

**Числа и имя поля выше — демонстрационные!** Подставлять только фактические ID из настроек изолированного смарт-процесса. Если он не создан, ничего не выполнять. Параметры webhook, доступы, роли должны выдать уполномоченные сотрудники заказчика; доступ к рабочим сделкам не нужен.

## Чёткие критерии GO / NO-GO

**GO на следующий этап:** 1) реальная официальная RSS с проверенными номером и оригиналом; 2) подтверждённый юридический ИНН покупателя, размер ФНС, район Москвы/МО; 3) действующий внешний запрос услуги 1С и актуальный срок; 4) законный корпоративный канал; 5) проверка дублей и стоп-листа; 6) решение менеджера; 7) администратор CRM разрешил изолированный тест; 8) CI/Windows тесты успешны.

**NO-GO на отправку в корпоративную CRM и клиентам:** любое пропущенное подтверждение выше. Локальный score или AI-гипотеза не могут заменить факты. Договоры, выручка, МRR и звонки пока не подтверждены. Код не затрагивает VALYQON.

Эти условия соответствуют заказанному MVP, а не самостоятельному сервису поиска любых тендеров.
