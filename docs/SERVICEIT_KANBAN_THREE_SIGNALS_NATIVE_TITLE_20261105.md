# Сервис ИТ — три направления нового Канбана (production title writer)

## Точное требование

Для всех будущих новых реальных карточек **смарт-процесса 1062 / категория 21**:

- 📑 **ТЕНДЕР** · исходное название
- 👥 **ВАКАНСИЯ** · исходное название
- 🎯 **ПРЯМАЯ УСЛУГА** · исходное название
- ⚪ **УТОЧНИТЬ ТИП** · исходное название — только если классификация неоднозначна

Нативное поле `title` обязательно показывается на плитке Канбана, в отличие от опционального `AI_SUMMARY`. Поэтому новая облачная автоматизация `serviceit-kanban-three-signal-title-auto.yml` пишет **только поле title** новой карточки, строго с сохранением исходного текста (без обрезки). Если карточка уже содержит подходящий значок, она не переписывается; если указан другой значок, результат HOLD до проверки, а не насильственная замена. Обработчик применяет строго те же классификационные правила, что и `AI_SUMMARY`, на основе известных метаданных вида сигнала и заголовка, без пересылки CRM данных в LLM.

Запуск: подписанное событие `serviceit_bitrix_item_add_v1`, резервный cron каждые 20 минут, и владелец может разово инициировать маркер `SERVICEIT_KANBAN_3_SIGNAL_TITLES_ONCE_V1` в Issue #200. Только новые карточки после ранее установленной даты cutover, без исторических #3/#7, других смарт-процессов, воронки поддержки, задач, score, контактов, стадий и исходных полей. Ключи GitHub и зашифрованная одноразовая запись предотвращают слепые повторные попытки при неоднозначном результате REST. Изменения фиксируются точным `crm.item.get` readback; отсутствие подтверждения не объявляется успехом.

## Общий вид Канбана для всех сотрудников — отдельное действие администратора

Нативные заголовки с эмодзи автоматически видны в обычном Канбане, поскольку это название плитки. Для красивых **дополнительных полей** (AI-вывод, HOLD/AI-статус, цветной приоритет, Score, направление услуг) корпоративный администратор один раз должен включить **настройку карточки просмотра в Канбане для всех сотрудников** в процессе 1062/21:

1. Название
2. `UF_CRM_13_SVCIT_AI_SUMMARY`
3. `UF_CRM_13_SVCIT_AI_STATUS`
4. `UF_CRM_13_SVCIT_AI_SCORE_BADGE`
5. `UF_CRM_13_SVCIT_LEAD_SCORE` — только подтверждённый score
6. `UF_CRM_13_SVCIT_SUGGESTED_SERVICE`

Если Bitrix UI ограничивает набор/тип полей мини-плитки, приоритет AI_SUMMARY + AI_SCORE_BADGE. Проверить браузером под двумя сотрудниками, убедиться, что персональные виды не переопределяют общий. Настройка полной формы внутри карточки `crm.item.details.configuration.get/set` НЕ заменяет настройки плитки Канбана. Текущий вебхук «Разработчик» 1615 не имеет подтверждённых прав администратора; без фактического UI-readback нельзя заявлять, что общий вид включён.

Не превращать тип «Вакансия» в продажу без подтверждения потребности, разрешения контакта и менеджерского решения. Не подставлять фиктивный Lead Score и не маркировать HOLD как подтверждённую продажу.
