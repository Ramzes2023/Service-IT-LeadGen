# Сервис ИТ — Gmail B2B V9: автоматический источник без ручного создания карточек

## Цель и схема

Проверенная архитектура: новая закупка B2B-Center → уведомление Gmail →
**отдельный** Gmail Apps Script (триггер раз в 5 минут) → подписанное событие
GitHub Actions → проверка дублей по source ID → зафиксированное одноразовое
создание HOLD в Bitrix24 1062/21 → независимый `crm.item.get` с проверкой
записанных девяти AI-полей → зашифрованный receipt ID. При отдельно одобренном
вызове GigaChat отправляется только **публичное название тендера**.
Потребитель не принимает решений по контактам или стадиям и не пишет
неподтверждённый квалификационный Lead Score.

Выгрузка **каждой** карточки, созданной вручную в Битрикс24, требует
настоящего события создания/робота портала. Это НЕ решается только Gmail:
исходящий вебхук текущему пользователю пока недоступен, а автоматический
опрос `crm.item.list` показал невалидную форму `[[]]`. Не утверждать LIVE
до создания и проверки источника такого события.

## Исправление V9

Предыдущий установщик V8 требовал найти ровно один старый проект Google Apps
Script по заголовку. У владельца поиск такого проекта не подтверждён;
одновременно отдельный Google Bitrix Event Bridge уже создан.

Новый `scripts/INSTALL_SERVICEIT_FREE_B2B_AUTOMATION_V9.ps1`:
- `без -Apply` — безопасный предварительный просмотр, без передачи секретов.
- `-Apply` — однократное разрешённое развёртывание (не на каждую карточку).
- Использует только существующие шифрованные DPAPI-ключи текущего владельца.
- **Сначала** отключает GitHub B2B вход, проводит положительную + отрицательную
  **только на чтение** проверку точного CRM поиска дублей. Контрольный известный
  источник B2B-Center №4665948 уже был отмечен в проекте как существующий в CRM.
  Искусственная незнакомая контрольная запись должна отсутствовать.
  Если вернуть `[[]]`, недоступную известную карточку или некорректный формат,
  остановиться с `SERVICEIT_B2B_EXACT_DUPLICATE_PROBE_BLOCKED_NO_AUTOMATION`
  и не создавать новые карточки.
- При успешном доказательстве создаёт **новый отдельно именованный**
  Google Apps Script `Service IT Gmail B2B Automated Intake V9`. Его ID
  сохраняется локально в `%LOCALAPPDATA%\ServiceIT\AI-Autofill\Gmail-B2B-V9\script-id.txt`;
  повторный запуск переиспользует только его. Он не переписывает существующий
  Google проект Bitrix24.
- Загружает скрипт из актуального `main`, с резервной копией, сравнивает
  SHA-256 кода, манифеста и приватного файла после readback и только затем
  включает GitHub ingest. Никаких паролей или токенов в stdout, файлах
  репозитория и публичных комментариях.
- Открывает Google редактор для **однократного** разрешения исполнения
  `installPollingTrigger()`. Google требует выдачу OAuth разрешений
  пользователем: нельзя программно обойти эту проверку. После неё
  **каждая новая** поддерживаемая B2B закупка обрабатывается без ручного ввода,
  даже при выключенном компьютере.

## Текущие подтверждённые ограничения

- Тесты GitHub — только синтетика. В реальном портале 2026-11-03 `crm.item.list`
  вернул `NESTED_EMPTY`, а чтение по ID работало. Сначала нужна
  **положительная** проверка существующего B2B источника, иначе автоматический
  импорт новых карточек остаётся выключен. Не воспринимать пустой/неверный
  список как доказательство отсутствия дубликата.
- Базовый AI может дать GigaChat-гипотезу по публичной теме. Итоговый
  проверенный Score требует достоверных фактов (покупатель, ФНС/ИНН, регион,
  актуальность закупки, клиент в CRM, стоп-лист, разрешение контакта).
  До автоматизации этих проверок статус честно остаётся HOLD, а не
  «полноценный квалифицированный лид».
- Для новых карточек от **всех** других создателей нужна отдельная
  интеграция событий Битрикс24; никакого обхода технических прав.
- Google Apps Script и GigaChat могут иметь квоты/стоимость по учётным условиям.
- Автоматизация CRM, outreach, менеджеров, стадий и истории не меняется.
