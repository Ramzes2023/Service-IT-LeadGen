# B2B-Center — первый этап подключения источника коммерческих B2B-закупок

**31 октября 2026. Модуль исследования; не live API и не Битрикс24.**

## Почему выбран

- На B2B-Center компании сами публикуют **коммерческие закупки услуг**, в том числе 1С, IT-инфраструктура, внедрение CRM и другие направления ООО «Сервис ИТ».
- Главный пилот Микаила: **Москва и Московская область, микро/малые компании**. Девять направлений полного ТЗ: 1С, IT-аутсорсинг, ККТ/маркировка, торговое оборудование, ЭП/КриптоПро/ЭДО, Битрикс24/CRM, серверы/сети, интеграции, чат-боты/ИИ.
- **Важно:** общий публичный поиск B2B-Center **агрегирует** 44-ФЗ, 223-ФЗ и закупки других ЭТП, поэтому нельзя считать все выдаваемые результаты собственными коммерческими процедурами, а тем более малыми B2B-заказчиками.

## Официальный API

Компания B2B-Center [29.07.2025 сообщила об обновлении API](https://www.b2b-center.ru/news/?id=520). Описание методов, образцы XML и сведения о доступности методов по тарифам находятся **в личном кабинете участника**. Из одной новости нельзя вывести существование нужного нам метода поиска закупок для поставщика, его адрес/тариф/формат. **Не выдумывать HTTP endpoints** и не использовать недокументированный парсер HTML.

Что требуется от владельца или администратора аккаунта компании: получить официальную спецификацию поддерживаемого API-метода **получения закупок/извещений для поставщика**, разрешение на систематическое использование данных, условия тарифа, схему авторизации и пример обезличенного XML/JSON. Если такого API-метода нет — согласовать официальный экспорт и использовать адаптер ниже. Пока **B2B_LIVE_API=NOT_CONNECTED**. Подписку/тариф без подтверждения полезности и условий не покупать.

## Что реализовано в `leadpilot.b2b_center_source`

Полностью **offline** приём нормализованного набора из *разрешённого оператором* API/экспорта (НЕ схема самого API поставщика, неизвестная нам сейчас), под строгий контракт `B2B_CENTER_APPROVED_EXPORT_NORMALIZED_V1`:

- 1–100 записей, не более 256 КБ, обязательные поля и строгий HTTPS URL **конкретной процедуры** на `www.b2b-center.ru`;
- собственные коммерческие процедуры против чужих 44-ФЗ / 223-ФЗ; название покупателя, **его** ИНН (не только организатора), контрольная сумма, Москва/МО;
- девять групп услуг; признак заявки на услуги, публикация не старше 30 дней, будущий дедлайн;
- сверка **по точному ИНН** с уже независимо подтверждённым реестром МСП ФНС (`SME_FIRST_FNS_SIZE_ONLY`); при отсутствии фирмы в выгрузке — HOLD, не ложный вывод «крупная»;
- один ID на процедуру (несколько процедур одной компании остаются разными сигналами), запрет перезаписи отчёта и Excel-формул;
- всегда `source_verified_live=false`, `crm_ready=false`, `qualified_real_leads=0`, `outbound_authorized=false`, `crm_writes=NO`.

Скрытые карточки, чужие данные, контакты сотрудников и реальные сообщения не собираются. Самозаявленное `source_origin` **не доказывает разрешение** — его нужно подтвердить документально.

### Формат подаваемого оператором нормализованного JSON

Это **схема для нашего проекта, не официальная схема API B2B-Center**. Не заполнять вымышленными реальными данными.

```json
{
  "mode": "B2B_CENTER_APPROVED_EXPORT_NORMALIZED_V1",
  "items": [
    {
      "procurement_id": "NNNNNNN",
      "source_url": "https://www.b2b-center.ru/search/number/lNNNNNNN-4-12-1/",
      "source_origin": "AUTHORIZED_OPERATOR_EXPORT",
      "procurement_class": "COMMERCIAL_B2B_CENTER",
      "buyer_inn": null,
      "buyer_name": "Название заказчика из исходной процедуры",
      "buyer_inn_role": "UNVERIFIED",
      "buyer_region": "Москва",
      "title": "Оказание услуг по сопровождению системы 1С",
      "description_excerpt": "Описание фактической потребности из оригинального запроса, не менее 20 символов",
      "published_on": "2026-10-30",
      "deadline_on": "2026-11-06"
    }
  ]
}
```

`NNNNNNN` — **только иллюстрация структуры** (модуль отвергнет такой ID); использовать реальный идентификатор, URL и подтверждённое право на обработку. Если **именно ИНН покупателя** установлен по оригинальной процедуре, указать его и `BUYER_CONFIRMED_FROM_PROCEDURE`; `ORGANIZER_ONLY` означает, что ИНН принадлежит организатору и нельзя использовать его для квалификации покупателя. Тип происхождения — `APPROVED_API_EXPORT` или `AUTHORIZED_OPERATOR_EXPORT`; оба требуют внешнего подтверждения законного права.

### Запуск из корня проекта

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_b2b_center_source.py
.\.venv\Scripts\python.exe -m leadpilot.b2b_center_source --input exports/b2b_authorized_normalized.json --fns exports/sme_first_moscow_50.json --output exports/b2b_center_research_01.json --csv exports/b2b_center_research_01.csv
```

Файл `exports/b2b_authorized_normalized.json` должен **уже существовать** и содержать разрешённые фактические данные. Если его нет, скрипт честно остановится, не подменяя результат образцами. ФНС-выгрузка 50 фирм покрывает только эти 50 ИНН: для новых покупателей сначала пополнить официальную проверку МСП по новым ИНН. Если ФНС-файл ещё не готов, `--fns` можно опустить, но тогда **все кандидаты будут в HOLD**.

## Минимальная приёмка настоящего источника

1. Официальный API-метод для поставщика или разрешённый экспорт подтверждён провайдером (доступ, тариф, условия), а не придуман.
2. Первая **реальная** выборка собственных активных коммерческих IT-заявок за 7–14 дней: журнал URL, покупатель, доказанный ИНН, город, предмет и статус.
3. ФНС проверяет размер именно заказчика; малые компании Москва/МО; отдельные HOLD по закрытому тендеру, 44/223-ФЗ, крупному или неподходящему заказчику.
4. Есть корпоративный или площадочный законный канал отклика, не скрытые персональные контакты; проверить поставщика на возможность участия.
5. Версионированный Lead Score, объяснение для менеджера, source/дата/следующее действие; после этого отдельное согласование CRM-дублей, стопов и первого теста в Битрикс24. **Пока Битрикс не трогать по указанию владельца.**
6. Подтверждённые `LIVE_FETCH`, `FNS_MATCHED`, `ACTIVE_COMMERICAL_BUYERS`, `MANAGER_READY` — наблюдаемые числа, а не план. Если ноль, **не объявлять источник READY**.

Остальные части ТЗ v3.0 — звонки/коммуникации, интеграция с действующими ботами, сделки, аналитика выручки/MRR и отдельный финансовый модуль РВП/мотивации — не скрываются и не считаются завершёнными после подключения источника.
