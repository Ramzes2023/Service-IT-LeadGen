# Сервис ИТ — воронка руководителя, реальный read-only счётчик

ТЗ Микаила: найдено → квалифицировано → контакт → интерес → КП → договор → выручка/MRR. Считать реальный результат, а не количество попыток звонков.

Сейчас подключён безопасный ежедневный отчёт в GitHub Actions: выводятся число реально обнаруженных после cutover сигналов в доступном смарт-процессе 1062/21 и состояние прав. В отчёте **нет** клиентских названий, ИНН, сумм и личных данных. Ручной запуск: комментарий владельца SERVICEIT_SUPERVISOR_FUNNEL_READONLY_ONCE_V1 в Issue #148.

До доказанного связанного события запись «квалифицирован», «контакт состоялся», «интерес подтверждён», «КП отправлено», «договор подписан», «оплачено» и «MRR» остаётся **НЕ ПОДТВЕРЖДЕНО**, не нулём. Завершённое дело CRM само по себе не является доказательством состоявшегося звонка. Пустая или невидимая отдельная воронка «Лидогенерация» не даёт права считать сделки техподдержки.

Администратор Битрикс24 должен отдельно предоставить или создать воронку сделок «Лидогенерация» и связку Лид/Сигнал ↔ Сделка. Финансовая роль должна подтвердить поступившую выручку и абонентский договор для MRR; сумма сделки (opportunity) не равна полученной выручке.

Для послеразговорной записи менеджер вводит подтверждённые итоги, интерес, следующее действие и срок. Готов модуль превью `leadpilot.manager_after_call.draft`, который не позволяет подменять факты выводом AI и не пишет в CRM без независимой проверки роли и прав. В дальнейшем менеджерское подтверждение должно быть связано с конкретным завершённым делом `crm.activity.list` и только затем с `UF_CRM_13_SVCIT_MANAGER_NEXT_ACTION` или задачей.

Текущая интеграция намеренно **только чтение**, чтобы не менять существующую техподдержку и не создавать фиктивные сделки.
