# Service IT — квалификация DEMO-сигнала, Lead Score и AI → Bitrix24

Версия: 1 ноября 2026. Это **следующий ограниченный этап** после подтверждённой учебной задачи Bitrix24 №26163 в карточке №3. **Не является производственным подключением реальных клиентов**.

## Что подтверждено до запуска

- На `serviseit.bitrix24.ru` существует только целевая учебная карточка `entityTypeId=1062`, `categoryId=21`, `id=3`, `DEMO-ITREQ-001`.
- На живом портале уже прошло пять независимых metadata gates, включая корректную зарегистрированную непровальную стадию категории 21.
- Учебная задача №26163 связана с карточкой через `UF_CRM_TASK=T426_3`, исполнитель — подтверждённый владелец ранее разрешённого вебхука.
- Никакого доказательства глобального сканирования действующих клиентов, стоп-листа, продажи или реальных лидов это НЕ предоставляет.

## Реализовано в коде

`leadpilot/bitrix_1062_demo_qualification.py`:

1. Повторно получает и строго подтверждает identity **только существующей синтетической карточки №3**, сохранённые 16 UF, stage policy, отсутствие связей с реальными клиентами, выключенную автоматизацию.
2. Использует уже существующий `core.score_company`, `SCORE_VERSION=mvp-2026-10-v1`, дату учебного сигнала из карточки и неизменённый учебный сценарий «три магазина; 1С + ККТ». Числовая оценка не берётся из свободного текста модели. При известных тестовых условиях получается `90/100` — **это учебный балл, не вероятность покупки**.
3. Стоп: реальное обращение запрещено, существующий нестандартный STOP_REASON нельзя переписать; если источник, ИНН, название, контакты или исходное состояние не соответствуют DEMO, остановка.
4. Не притворяется глобальной CRM-дедупликацией: указывает `global_customer_dedup=NOT_VERIFIED`. Прежний локальный механизм `core.ingest` нормализует ИНН и допускает несколько независимых сигналов одной компании, а `workflow_ops` блокирует стоп/действующих клиентов. **Глобальные права к корпоративным клиентам не выданы и в этом PR не запрашиваются.**
5. AI через существующий `classify_authorized_signal` работает **только при отдельном** `-WithSyntheticAI` и `AI_ENABLE=1` с настроенным провайдером. Модели передаётся только короткая вымышленная фраза без данных сотрудников и клиентов. Результат принимается исключительно как `AI_hypothesis` с подтверждаемой дословной цитатой и `quality_status=complete`, иначе запись блокируется. AI **не изменяет Lead Score**. Если AI не вызывался — в CRM явно отображается `AI=НЕ ЗАПУЩЕН`.
6. Режим preview только читает Bitrix и рассчитывает данные; **никаких изменений по умолчанию**.
7. Вручную запускаемый `-ApplyDemo` может сделать **ровно один ограниченный `crm.item.update` только для карточки №3**, передавая четыре ранее созданных поля:
   - `UF_CRM_13_SVCIT_LEAD_SCORE`
   - `UF_CRM_13_SVCIT_SCORE_VERSION`
   - `UF_CRM_13_SVCIT_MANAGER_NEXT_ACTION`
   - `UF_CRM_13_SVCIT_STOP_REASON`

Нельзя менять stage, ID, контакт, компанию, другие UF, создавать новые карточки, задачи, исходящие коммуникации. **Не делать` tasks.task.add` повторно: №26163 уже существует.**

Перед POST используется отдельный локальный SQLite ledger `%LOCALAPPDATA%\ServiceIT\One-Demo-Qualification\sync.sqlite3` с уникальным одноразовым ключом и состоянием `POST_OUTCOME_UNCERTAIN`. Если запрос оборвётся, **не повторять POST вслепую**. После update выполняется `crm.item.get` и независимая metadata revalidation, затем state `VERIFIED`.

## Запуск на закреплённом коммите

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/RUN_SERVICEIT_DEMO_QUALIFICATION_BRIDGE.ps1
```
Это только read-only preview. Флаг `-ApplyDemo` отдельно разрешает единственную запись **в четыре поля учебной карточки №3**, что может создать внутреннее событие CRM. Для AI нужен `-WithSyntheticAI`, предварительно `AI_ENABLE=1` и отдельные провайдерские переменные, без передачи секретов в GitHub/чат. Вебхук вводится локально через скрытый PowerShell prompt.

## Что не выполнено в задании Михаила

Это **не** проверка реальных клиентов компании, их ИНН, реальных телефонных стоп-листов или глобальной CRM-дедупликации. Не подключены автоматически новые внешние источники и не включён промышленный worker. Нет реальной проверки AI на коммерческих данных или оценки качества реальных лидов, контактов/продаж. Для подключения этих частей нужны отдельные безопасные права и политика минимального доступа к данным заказчика с human-review.

Официальный метод `crm.item.update`: https://apidocs.bitrix24.ru/api-reference/crm/universal/crm-item-update.html .

## Результат приёмки

`DEMO_PREVIEW_READY` — полная проверка и расчёт без CRM update.

`DEMO_CRM_QUALIFICATION_VERIFIED` — **только тогда** подтверждена одна настоящая DEMO-запись и повторное чтение.

`ALREADY_MATCHES` — поля уже совпадают, запись не производилась.

`BLOCKED_OR_UNCERTAIN` — не повторять `-ApplyDemo` до проверки журнала и карточки.
