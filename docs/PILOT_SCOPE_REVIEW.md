# Дополнительный фильтр: целевой сегмент первого пилота

## Почему он нужен

Из 15 кандидатов по вакансиям 1С встречаются средние, крупные и публичные организации. Это само по себе не ошибка API: код берёт ИНН из поля company ответа вакансии, но **одна вакансия 1С ещё не подтверждает готовность заказать наши услуги**.

Первый пилот для ООО «Сервис ИТ» — малые компании Москвы и Московской области, нуждающиеся в сопровождении 1С. Размер бизнеса проверяется по ИНН и актуальной записи в реестре ФНС, а не по косвенным признакам или названию. Третьи лица (коммерческие справочники) могут дать сигнал для проверки, но не подменяют официальный реестр.

## Команды PowerShell

Используйте существующий локальный checklist, без передачи реальных контактов в GitHub:

    .\.venv\Scripts\python.exe -m leadpilot.pilot_scope_review prepare
    .\.venv\Scripts\python.exe -m leadpilot.pilot_scope_review audit

Команда prepare один раз создаёт файл exports/mvp_scope_review.json. Если он уже существует, ручная работа **не перезаписывается**. Команду audit можно запускать повторно.

## Поля решения

Для каждого ИНН:
- decision — PENDING, PROVISIONAL_SMALL, DEFER или EXCLUDE;
- reported_business_type — unknown, micro, small, medium, large, public_institution или other;
- reason — SIZE_OUT_OF_SCOPE, PUBLIC_INSTITUTION, NOT_1C_BUYER, UNVERIFIED_ORGANIZATION, OTHER или пустая строка;
- evidence_url, evidence_date в формате YYYY-MM-DD, evidence_text и reviewed_by;
- notes — внутренний комментарий без персональных данных.

EXCLUDE с документированным подтверждением — только исключение из **первого пилота**, а не глобальный CRM-стоп-лист. PROVISIONAL_SMALL — предварительное соответствие, но **не подтверждение ФНС**. DEFER оставляет компанию для проверки позднее.

## Ограничения

Система не проводит автоматическую проверку источника по сети: правильный HTTPS URL ещё не означает, что источник подлинный и относится к данному ИНН. Реестр ФНС, дату, причину и целесообразность решения проверяет человек.

При любой записи значение crm_ready=0. Никаких созданий Лидов/Сделок в Битрикс24, рассылок, звонков или изменений в VALYQON. Проверка на дубль внутри корпоративного Битрикс24 остаётся отдельным этапом после выдачи прав.

GitHub issue #8 содержит найденные примеры потенциально нецелевых организаций; коммерческие источники нельзя считать официальной категорией ФНС.
