# Этап 4: реальный охват CRM и официальный доступ ФНС

## Реальный аудит вебхука

GitHub Actions `serviceit-stage4-crm-read-coverage.yml` раз в день и по owner-комментарию `SERVICEIT_STAGE4_CRM_COVERAGE_READONLY_ONCE_V1` проводит чтение только метаданных и первых страниц ID существующих компаний и контактов в CRM + точной контрольной выборки реквизитов с синтетическим ИНН. Ни одна запись не создаётся или не меняется. **В публичных логах нет ИНН, ФИО, названий компаний, ID, клиентских данных.**

Проверяет: `crm.company.list`, `crm.contact.list`, `crm.requisite.fields`, `crm.requisite.list`, `user.admin`. Граница API — права пользователя, который создал REST вебхук; полный доступ ко всей CRM **нельзя** доказать одним успешным `list`. Даже полный ответ `crm.requisite.list` не исключает скрытых пользователю объектов и иных форм дублей, например компании без реквизитов.

Результат `full_corporate_crm_coverage_verified=false` — честный блокирующий статус, пока сотрудник с соответствующими правами не подтвердит состав и границы корпоративных CRM данных и будет настроен безопасный полный dedup.

## Как подключить официальную ФНС

Проверено 04.11.2026 по ФНС:

- Бесплатная подписанная электронная выписка **по конкретному ИНН**: https://egrul.nalog.ru/ и https://www.nalog.gov.ru/rn77/related_activities/registries/egrul_egrip/ . Поисковая веб-форма — **не документированный промышленный API**, нельзя скрыто автоматизировать запросы и затем утверждать «достоверно проверено».
- Для прямого промышленного загрузчика XML ЕГРЮЛ/ЕГРИП ФНС выдаёт атрибуты доступа по отдельному обращению; обычным коммерческим пользователям предоставляется **за плату**: https://www.nalog.gov.ru/rn77/service/egrip2/access_order/ . Технический режим и XML архивы: https://www.nalog.gov.ru/rn77/service/egrip2/egrip_vzayim/ .
- В 2026 году официальные форматы XML: ЕГРЮЛ **4.08**, ЕГРИП **4.07**; старые 4.07 / 4.06 действуют до 22.01.2027. Их нельзя путать с XML **МСП**, который наш валидатор уже обрабатывает отдельно.
- Официальные открытые сведения МСП требуют достоверно загруженный датированный ZIP, точный URL и независимый SHA256; без них модуль возвращает HOLD. Не считать факт включения в МСП равнозначным действующему статусу компании в ЕГРЮЛ.

## Что нужно от компании для истинного VERIFIED Score

1. Утвердить **объём чтения корпоративной CRM** для технического пользователя вебхука: компании, контакты, реквизиты, коммерческие сделки и другие релевантные объекты (включая видимость всех ответственных сотрудников); исключить исторические карточки только из записей, а не из проверки дублей. Достаточный охват подтвердить независимым администратором.
2. Выбрать официальный доступ ФНС для многоразового машинного получения ЕГРЮЛ/ЕГРИП либо подтверждённый корпоративный канал для получения подписанных выписок; обеспечить хранение/валидацию электронных подписей и свежесть доказательств.
3. Согласовать отдельную политику **предварительной** оценки, пока STOP-лист компании не существует. Отсутствие STOP-листа не означает `STOP=CLEAR`; контакты и конечная передача менеджерам запрещены без отдельного решения.

Модуль `stage4` для окончательного Lead Score не включать от имени одного вебхука или по неподтверждённым данным. Следующий этап — согласование доступа ФНС и full-CRM и реальное receipt-подтверждение с независимой подписью.

Ни один пробный запуск не должен создавать фиктивные CRM карточки или трогать `#3`, `#7`, обычную воронку технической поддержки.
