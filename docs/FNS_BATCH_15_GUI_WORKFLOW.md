# Быстрая сверка 15 компаний с официальным реестром МСП ФНС

Найден более удобный официальный маршрут, чем многогигабайтная загрузка всего реестра: на сайте ФНС имеется **режим «Поиск по списку ИНН»**.

Официальная страница:
https://rmsp.nalog.ru/search.html?mode=inn-list

Поиск по списку ИНН и кнопка «Экспорт в Excel» подтверждены непосредственно интерфейсом ФНС на 31 октября 2026 года. ФНС также предлагает выгрузку индивидуальных сведений в PDF с электронной подписью для уточнения категории предприятия.

## Шаг 1. Подготовить список на Windows

На текущем этапе отчёт содержит 15 кандидатов. В корне репозитория:

    .\.venv\Scripts\python.exe -m pytest -q
    .\.venv\Scripts\python.exe -m leadpilot.fns_batch_prepare

Выход в файл exports/fns_batch_inns.txt: один ИНН на строку, без названий и контактов. Код только читает существующий exports/mvp_scope_review.json. Существующий файл INN не перезаписывается. Для альтернативного формата, если потребуется: --separator comma --output exports/fns_batch_comma.txt.

## Шаг 2. Проверить на сайте ФНС

1. Открыть https://rmsp.nalog.ru/search.html?mode=inn-list.
2. Скопировать содержимое локального файла exports/fns_batch_inns.txt и вставить в поле «Список ИНН». Если поле не принимает строки, попробовать список через запятую (опциональная настройка выше).
3. Нажать «Найти». Проверить, какие записи найдены, актуальность среза, ИНН и категории МСП.
4. При необходимости нажать «Экспорт в Excel», сохранив файл локально **в exports/**, например exports/fns_official_batch_20261031.xlsx.
5. Для предполагаемых перспективных микро- и малых компаний получить индивидуальную PDF-выписку ФНС с электронной подписью и подтвердить запись по ИНН.
6. Если организация не найдена, не делайте вывод «крупная»: возможны неполные данные, дата среза, ошибка поиска или иное юридическое основание. Оставьте статус UNKNOWN и проверьте отдельно.

## Шаг 3. Дальнейшая интеграция

Автоматический импорт Excel пока **не реализован**, поскольку точные столбцы реальной выгрузки ещё не подтверждены проверенным файлом. После получения официального XLSX разработать валидатор: сопоставление по ИНН, дата среза, реальная категория, отклонение неизвестных столбцов/дубликатов, provenance и резервная копия. Сразу создавать лиды в Битрикс24 **нельзя**.

Статус должен оставаться crm_ready=0, пока не проверены CRM-дубли, разрешённый контакт, актуальность потребности и права в корпоративной системе. Даже подтверждение категории «малое» ещё не доказывает, что организация заинтересована купить поддержку 1С.

## Техническая безопасность

- Никаких неописанных POST API ФНС или обхода доступа: процесс использует пользовательский интерфейс официального сайта.
- Никаких автоматически открываемых ссылок из пользовательских данных, исходящих сообщений, запросов к рабочему Битрикс24 и изменений VALYQON.
- Файл INN, Excel/PDF и все локальные документы исключены из Git через правила /exports/.
- Введённая в XML/Excel информация не считается проверенной до сверки её официального происхождения.
- GitHub Actions репозитория ранее завершался до запуска шагов; не объединять PR до решения issue #7 и реальных проверок.
