# ServiceIT: видимые разделы «AI-анализ» и «Проверка менеджером»

Проверено по официальным Bitrix24 REST API:
- [get](https://apidocs.bitrix24.ru/api-reference/crm/universal/item-details-configuration/crm-item-details-configuration-get.html)
- [set](https://apidocs.bitrix24.ru/api-reference/crm/universal/item-details-configuration/crm-item-details-configuration-set.html)

**Особенность:** `crm.item.details.configuration.set` **полностью заменяет**
конфигурацию формы. Отправить один новый раздел без текущей формы нельзя —
остальные разделы могут исчезнуть. Без администраторских прав нельзя менять
общую форму сотрудников `scope=C`. Параметр конкретной воронки обязателен:
`extras: {categoryId:21}` при `entityTypeId:1062`.

## Что добавляет безопасный план

Существующие разделы/поля, порядок, visibility flags и настройки полей
сохраняются **без изменения**. В наличии текущего полного layout подтверждается
методом `get`; `null` и повреждённый ответ — стоп. Из каталога
`crm.item.fields` проверяются 15 уже существующих полей:

- Сервис ИТ | AI-анализ: 9 текстовых AI-полей + 3 score-поля;
- Сервис ИТ | Проверка менеджером: следующее действие менеджера, решение
  менеджера и причина STOP.

Если поле уже отображается в другом разделе, оно не дублируется и
автоматически не перемещается. В ином случае оно добавляется в целевой
раздел с `optionFlags=1` (всегда видно, даже если пустое).
Существующие разделы и поля не удаляются.

## Применение без локального ноутбука

GitHub Actions `ServiceIT manager and AI form layout (guarded free)`:
- ручной `workflow_dispatch` по умолчанию **preview/read-only**,
  вообще без Bitrix writes;
- `apply=true` существует только при одновременных условиях:
  `SERVICEIT_MANAGER_LAYOUT_APPLY=YES_1062_21_SHARED_MANAGER_LAYOUT`
  и `SERVICEIT_MANAGER_LAYOUT_ADMIN_APPROVED=YES` в GitHub variables,
  действующий корпоративный admin-webhook и Fernet secret;
- перед сохранением повторно читает форму и сравнивает hash;
- **до первого Bitrix set** делает зашифрованный GitHub backup старой и новой
  *полных* конфигураций в `serviceit-ai-encrypted-ledger`;
- при неоднозначном подтверждении backup **не выполняет Bitrix set**;
- после `set` выполняет `get` и сравнивает всю форму; если ответ не совпал —
  **UNCERTAIN_NO_RETRY**, а не слепая перезапись.

Никакого `crm.item.add/update`, стадий, `tasks.task.add`, телефонных
вызовов, массовых сообщений, письма, GigaChat, финансов или персональных
данных клиентов этот оператор не трогает. Полный layout (имена/параметры
полей) сохраняется только **зашифрованно**, не публикуется в stdout.
Для восстановления после сбоя требуется отдельная согласованная процедура.

## Что это НЕ делает

- Не обещает, что UI карточки уже изменился: реальный `apply` и readback
  не выполнялись, прав admin-webhook пока нет возможности подтвердить.
- Не превращает уведомление закупки из B2B-Center в подтверждённый лид.
- Не обходит CRM глобальный дедуп/STOP/юридическое основание контакта.
- Не включает платный AI/API, не создаёт задачи, звонки и рассылки.
- Не решает отражение персональных полей сотрудников: общий layout
  (`scope=C`) может перекрываться их индивидуальными настройками.

## Состояние выполнения

Код планирования и резервирования / mock HTTP E2E проверяется GitHub CI.
Корпоративное применение отдельно зависит от административного разрешения.
Внутри этого PR не производится ни одного реального CRM или GitHub
state-write вне исходного репозитория.
