# Бесплатный итоговый внутренний Lead Score — «Лидогенерация»

**06.11.2026.** Область: только новые реальные карточки `serviseit.bitrix24.ru`, смарт-процесс **1062 / категория 21**, созданные после cutover. Старые записи 3/7, «Техническая поддержка», существующие сделки, контакты, компании и источники не меняются.

## Отмена платных зависимостей

- **НЕ требуем** ЕГРЮЛ/ЕГРИП, коммерческий API выписок и платное «подтверждение активности» для внутреннего Lead Score.
- Используем **официальный бесплатный месячный XML/ZIP** ФНС-МСП: https://www.nalog.gov.ru/opendata/7707329152-rsmp/ . Уже существующий collector сохраняет **зашифрованную квитанцию** по точному ИНН и карточке.
- `MICRO`, `SMALL`, `MEDIUM` — категория из архивного снимка. Отсутствие в МСП = **размер неизвестен**, **НЕ** доказательство крупного бизнеса или отсутствия регистрации. Срез ФНС — не правовое подтверждение статуса и не доказательство спроса.
- Балл = существующий детерминированный приоритет сигнала + небольшой вес размера МСП: микро +0, малое +4, среднее +8, неизвестно +0; максимум 100. Это **внутренний приоритет работы с запросом**, не право на контакты, не сертифицированная коммерческая сделка.
- Для итогового статуса нужны девять заполненных полей AI-отчёта (они могут честно содержать HOLD), действительные ИНН, дата/HTTPS-ссылка сигнала за последние 30 дней, отсутствие локального дубля, отсутствие блокировки **собственного** STOP и точная зашифрованная квитанция бесплатного ФНС-МСП. Никакой платной выписки.

## Отдельный STOP-лист и дубли

`config/serviceit_own_signal_stop.json` — рабочий отдельный список **только для LeadGen**. `rules: []` означает «наш список пуст», а не «корпоративный STOP проверен». Управляется через GitHub PR, принимает точный ID карточки или валидный ИНН с причиной. Любой HIT блокирует новую оценку.

Обязательна полностью прочитанная доступная выдача дублей по ИНН **в нашем 1062/21**. Обнаруженный дубль → HOLD, без записи итогового Score. Сверх этого проверяются доступные реквизиты контактов/компаний всей корпоративной CRM: **положительное совпадение** → HOLD. **Недостаточные права, сбой API или отрицательный видимый результат НЕ считаются доказательством полноты всей корпоративной CRM.** В этом случае внутренний Score может быть рассчитан только по безопасной отдельной воронке; автоматическая рассылка и контакт остаются выключенными. Дополнительную CRM и вторую воронку не создаём — действующая отдельная 1062/21 уже существует.

## Облачная автоматизация

`.github/workflows/serviceit-leadgen-free-msp-internal-score.yml`:
- расписание каждые ~20 минут (GitHub Actions **best effort**, без строгого SLA);
- подписанное событие создания новой карточки;
- завершение официального ФНС-MSP collector при success после дополнительной проверки точного имени/репозитория/main/event внутри Python.

`leadpilot/serviceit_leadgen_free_msp_score.py` записывает **только** `LEAD_SCORE`, `SCORE_VERSION`, `AI_SCORE_BADGE` для ранее пустых или точно распознанных *собственных* предварительных Score. Manual/чужой/уже итоговый Score не перезаписывает. Версия `svc-leadgen-free-msp-v1` и текст `ВНУТРЕННИЙ ИТОГ · Контакт: нет` явно отделяют его от формального корпоративного nine-proof buyer contract. Отдельный encrypted one-use ledger резервируется **до** `crm.item.update`; после неопределённой записи запрещён слепой повтор; CRM readback обязателен.

Корпоративный **nine-proof formal verifier** намеренно не подделываем: он остаётся отдельной процедурой *внешнего/юридического допуска*, если заказчик когда-нибудь её потребует. Новый внутренний балл не наследует ни его платные требования, ни «verified buyer»/outreach, и не утверждает юридические факты.

## Приёмка

1. `python -m pytest -q tests/test_serviceit_leadgen_free_msp_score.py tests/test_serviceit_preliminary_score_markers.py tests/test_serviceit_stage4_provisional_score_live.py`.
2. Проверить успешный CI всех тестов, затем включить новую workflow в main.
3. Для настоящей **новой** карточки с действительной квитанцией официального ФНС убедиться по журналу GitHub, что `readbacks_verified=1`, а в Битрикс24 три поля совпадают и версия `svc-leadgen-free-msp-v1`. Если нет подходящей карточки, не объявлять сквозную интеграцию испытанной.
4. Никаких фиктивных ИНН, искусственных CRM-записей, повторных опасных мутирующих вызовов или контактов с клиентами ради проверки.

Ограничение: GitHub Actions часто запускаются с задержками; реальное выполнение одного cron и отсутствие ошибки кода не дают гарантию каждые 20 минут.
