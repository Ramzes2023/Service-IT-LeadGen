## Единственный недостающий интерфейс — действующий Google Apps Script

1. Войти в [Google Apps Script](https://script.google.com/home) под тем же Gmail. Открыть **существующий** проект, содержащий `checkB2BCenter`, `pollAndDispatchB2B` и рабочую HMAC-конфигурацию.
2. В единственном файле `Code.gs` заменить код проверенной версией из [GitHub main](https://github.com/Ramzes2023/Service-IT-LeadGen/blob/main/integrations/apps_script/Code.gs). Оставить `secrets.gs`, Script Properties, проект, его OAuth-разрешения и `appsscript.json` нетронутыми. Сохранить.
3. Запустить только `serviceITB2BDeliveryStatusReadOnly` (0 исходящих уведомлений, 0 записей CRM). Убедиться: `automation_enabled: true`, `vps_direct_enabled: true`, `trigger_count: 1`. Если триггер отсутствует, однократно выполнить `installPollingTrigger` и вновь проверить статус. **Не вызывать повторно `activateVpsB2BCenter`**, он не восстанавливает пропавший триггер после активации.
4. Запустить `diagnoseB2BCenterReadOnly`: проверить `NO_MATCH`, `REVIEW_REQUIRED` и ошибки Gmail API. Функции не раскрывают значения HMAC, контакты или содержание письма.
5. Однократно запустить `pollAndDispatchB2B`. После ревизии парсера до четырёх пост-активационных `NO_MATCH` **или `DONE`** писем пересматриваются в каждом цикле; если ранее пропущенный IT-тендер не имеет source receipt, только он отправляется через обычную подписанную доставку. Уже переданные ID повторно не отправляются. Проверить `last_poll_utc`, `vendor_messages_visible`, `pending_emails_scanned`, `recovered_missed_messages` в `serviceITB2BDeliveryStatusReadOnly`.
6. Проверить независимым READ-ONLY audit из GitHub и в Битрикс24 появление новых source IDs. Вновь запущенный скрипт не должен создавать дубли: `DISPATCH_UNCERTAIN` и `REVIEW_REQUIRED` **нельзя слепо сбрасывать**, сначала сверить PostgreSQL с Bitrix и реальным исходным письмом.

## География: только Москва и Московская область

- Проверяется **место исполнения** закупки, не юридический адрес компании.
- Источник подтверждения: точный номер + предмет в реально открытой разрешённой первичной/достоверной странице.
- №4677923 (Teams) — **Москва**, №4677837 (поддержка серверов) — **Краснодар**; эти две публичные закупки используются только для read-only проверки геофильтра.
- Географический фильтр уже активирован на VPS (run 43242302133): `B2B_GEO_MOSCOW_ONLY_ENABLED=YES`. Если по очередной закупке нет подтверждённого места исполнения (robots/403/JS), она может остаться в `REVIEW` без создания CRM-карточки. Нужна дополнительная разрешённая публичная проверка таких неизвестных закупок, а не подмена региона адресом регистрации заказчика.
- Проверка географии не тратит Brave, Tavily, TinyFish.

## Контроль после одного нового реального письма

Проверить три последовательных факта: (1) Gmail real message id находится в Script Properties как DONE или предусмотренное безопасное исключение; (2) source ID находится в VPS PG как VERIFIED/EXISTING или объяснимый REVIEW; (3) Bitrix имеет **ровно одну** карточку для московского source ID. При первом отсутствии фиксировать стадию `NO_MATCH/REVIEW_REQUIRED/DISPATCH_UNCERTAIN`, без повторных POST вручную.

**Важно:** GitHub с текущими разрешениями позволяет обновлять VPS, но не вызывать Google Apps Script API от имени данного Gmail; для изменения активного `Code.gs` требуется доступ к существующему проекту Google Apps Script. Отсутствие такого доступа — единственная неизменённая часть установленного контура.
