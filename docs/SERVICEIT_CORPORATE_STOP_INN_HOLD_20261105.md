# Сервис ИТ — корпоративный STOP, предварительная проверка точного ИНН

**Дата:** 05.11.2026. Полный corporate all-channel STOP пока не предоставлен. Этот компонент даёт только автоматический **положительный HOLD** для ИНН из утверждённого исключающего списка, не разрешает продажи, звонки, КП или окончательный Lead Score.

## Готовая реализация
- `leadpilot/serviceit_corporate_stop_inn.py`: точный HMAC-SHA256 по ИНН на независимом ключе, версия `serviceit-corporate-stop-inn-v1`, строгий контракт manifest, дедупликация, ограничение списка, защита от несовпадения scope и частичного включения.
- Уже действующий автоматический `serviceit-stage4-fns-dedup-readonly.yml` читает этот список в контексте новых карточек `1062/21`, **до** проверки МСП. Положительный результат `HOLD_CORPORATE_STOP_MATCH`; ошибочная конфигурация `HOLD_CORPORATE_STOP_CONFIG_UNVERIFIED`. В обоих случаях Score/контакты остаются запрещены.
- Отсутствующий список или отсутствие совпадения НЕ означает `STOP=CLEAR`: проверка обязательств по всем каналам, договорам, контактам, названиям компаний, действующим клиентам, отказам, согласиям остаётся отдельно.
- Ни одна историческая CRM-карточка не меняется; существующие источники, техподдержка и сделки не затрагиваются.

## Что требуется корпоративному владельцу STOP (однократно)
1. Утвердить **политику и охват** исключающих записей (например, запретные ИНН), официального владельца списка, порядок актуализации, периодичность и полномочия на проверку.
2. Подготовить в доверенной рабочей среде *отдельный секретный* HMAC ключ (случайный, не менее 32 символов) и manifest, полученный из утверждённого списка ИНН функцией `make_approved_manifest(list_of_valid_inns, key)`. В публичный репозиторий и Issue нельзя отправлять ИНН, исходный список, ключ, контактные данные, логи или ссылки-вебхуки.
3. Секреты GitHub `SERVICEIT_CORPORATE_STOP_INN_KEY` и `SERVICEIT_CORPORATE_STOP_INN_MANIFEST` загружает только корпоративный уполномоченный владелец; после явного одобрения включает `SERVICEIT_CORPORATE_STOP_INN_ENABLED=YES_1062_21_CORPORATE_INN_HOLD_ONLY` в repository vars.
4. Перед любой попыткой разрешить контакт оформить *отдельные* независимые доказательства по полной корпоративной STOP-политике и полному CRM customer/dedup; HMAC-проверка одного поля ИНН их **не заменяет**.

## Официальный ЕГРЮЛ/ЕГРИП — отдельный блок

Промышленное получение файлов ФНС ЕГРЮЛ/ЕГРИП для коммерческих организаций требует оформленного доступа и атрибутов доступа по официальному порядку ФНС: https://www.nalog.gov.ru/rn77/service/egrip2/access_order/ . Бесплатная выписка о **конкретной** компании (например, https://egrul.nalog.ru/) допускает человеческий документальный сценарий, но не является открытым промышленным API. Для автоматического VERIFIED статуса потребуются достоверные файлы, актуальная запись, проверка формата/подписи/источника и официальный регламент.

Информация ФНС-МСП — отдельное свидетельство о включении в реестр МСП на дату публикации и не доказывает действующий статус по ЕГРЮЛ/ЕГРИП. До подключения этих независимых контуров весь формальный Score остаётся HOLD.
