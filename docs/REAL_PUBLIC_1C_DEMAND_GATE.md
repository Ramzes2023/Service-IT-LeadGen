# Реальные публичные заявки на внешние услуги 1С → проверка по ИНН

## Что фактически произошло в PR #17

На Windows владелец подтвердил `179 passed (4.23s)` и `SME_VACANCY_AUDIT=SUCCESS`. Среди 50 микро-компаний, подтверждённых ФНС, **0 совпадений по ИНН** в четырёх уже сохранённых snapshots с вакансиями 1С. 17 вакансий отсечены по свежести, 20 не относятся к этим 50 ИНН, одна не 1С. `crm_ready=0`, данных о подтверждённом аутсорсинговом спросе нет. Это **не отсутствие спроса в рынке**, а отсутствие совпадений в маленькой выборке вакансий.

## Почему другой источник

Вакансия — поиск собственного сотрудника. Закупка или публичный запрос предложений — непосредственное свидетельство того, что *конкретный заказчик* рассматривал приобретение внешней услуги. При этом запись может быть закрыта, отменена, касаться только госучреждений, не относиться к 1С:Предприятию или не подходить сервисной специализации.

Проверенные публичные примеры **существования такого источника**, но **не лиды из наших 50**:

- B2B-Center, закупка №4616274, организатор и заказчик ООО «Системы реагирования и мониторинга», ИНН 7727448045: публичный запрос услуг сопровождения, технической поддержки, доработки на платформе «1С:Предприятие». Публикация 25.09.2026; срок подачи заявок **20.10.2026, уже прошёл**. https://www.b2b-center.ru/search/number/l4616274-4-12-1/ . **Не маркировать активной возможностью без новой проверки**.
- Москва, примеры свежих закупок на сопровождение 1С: https://zakupki.kontur.ru/category-region/1c/moscow . Реестр включает 1С-Битрикс24, лицензии и крупные/государственные закупки; это **не автоматическая выборка малых компаний**. Проверять каждое описание/заказчика.

Это два разных коммерческих направления: (а) B2B-лидогенерация микро/малых компаний для менеджера; (б) участие самого «Сервис ИТ» в публичных закупках. Совпадение понятий «МСП» в правилах допуска поставщика **не делает покупателя микропредприятием**. Для текущего MVP сохраняем только направление (а).

## Новый модуль `leadpilot.public_1c_demand_gate`

**Только офлайн.** Получает `exports/sme_first_moscow_50.json` плюс небольшой вручную подготовленный локальный JSON с **реальными публичными заявками** и обязательными полями:

```json
{
  "mode": "PUBLIC_1C_REQUESTS_MANUAL",
  "items": [
    {
      "buyer_inn": "ИНН_ЮЛ_10_ЦИФР",
      "source_url": "https://public-procurement-platform.example/ACTUAL-REQUEST",
      "source_type": "COMMERCIAL_TENDER",
      "title": "Реальное название закупки с 1С и сопровождением",
      "published_on": "2026-10-30",
      "deadline_on": "2026-11-10",
      "evidence_excerpt": "Короткая фактическая цитата/выжимка из публичного заказа",
      "verified_by_operator": false
    }
  ]
}
```

**Это иллюстрация структуры, а не реальная заявка; подставные значения выполнять нельзя.** URL должен быть реальным HTTPS-документом на поддерживаемой публичной площадке (zakupki.gov.ru, zakupki.mos.ru, B2B-Center, Росэлторг, РТС-тендер, ТЭК-Торг, Bidzaar и др.). Никаких паролей, непубличных аккаунтов, телефонов, email и переписок.

Дальнейшая команда, **только после получения реальной проверяемой выборки источников**:

    .\.venv\Scripts\python.exe -m leadpilot.public_1c_demand_gate --fns exports/sme_first_moscow_50.json --evidence exports/public_1c_requests.json --output exports/sme_public_1c_request_audit.json --csv exports/sme_public_1c_request_audit.csv

### Гейты и смысл статусов

- `PUBLIC_SOURCE_MANUAL_REVIEW`: точный **ИНН** совпал с микро/малым бизнесом и есть документированная заявка. **Не CRM-ready**; источник живой и статус процедуры программой не перепроверяются.
- `DEADLINE_PASSED_NOT_ACTIVE`: указанный срок подачи уже прошёл; не включать в текущие предложения.
- `DEADLINE_UNKNOWN_MANUAL_RECHECK`: срок не установлен — проверить вручную.
- `PUBLISHED_EXTERNAL_1C_REQUEST_REVIEW`: срок по записанным данным ещё не прошёл, но процедура может быть отменена/закрыта или непригодна — проверить сайт и условия вручную.
- `NO_DOCUMENTED_EXTERNAL_REQUEST_IN_SUBMITTED_ITEMS`: источника нет в **маленьком введённом списке**, а не «клиенту 1С не нужно».
- Если ИНН заказчика не входит в подтверждённые 50, он сохраняется **только в отдельный список для дальнейшей официальной проверки ФНС**, не получает статус малого бизнеса и не переходит в CRM.

Все этапы: `lead_score=null`, `crm_ready=false`, `outbound_authorized=false`, `crm_writes=NO`. Нет сетевых запросов, автоматических коммерческих сообщений, изменения Битрикс24, GigaChat, VALYQON. Локальные файлы — ignored `exports`; реальная закупка проверяется оператором и менеджером, а не принимается на веру из JSON.

## Состояние и дальнейший критерий успеха

Код добавлен в Draft PR поверх PR #17. Предыдущие **179 passed подтверждены пользователем**. Новые тесты ещё не прошли Windows/CI. Только **живой опубликованный запрос, реальный ИНН в ФНС (или отдельно официально проверенный), проверка технического задания и разрешённого канала взаимодействия** могут образовать кандидата на коммерческую квалификацию. Даже он не отправляется в Битрикс24 без проверки дублей и согласования.
