# ЕИС → проверка покупателя по ФНС (MVP «Сервис ИТ»)

## Причина доработки

ТЗ Микаила (письмо 30.10.2026): **небольшие покупатели Москвы и МО**, которым нужна **внешняя поддержка 1С**, затем менеджерская карточка и только с согласованными полномочиями Битрикс24. RSS ЕИС — реальный публичный источник сигналов **закупочной потребности**, но реестр 44-ФЗ/223-ФЗ часто включает государственные учреждения и крупные предприятия. Участие в закупке для поставщиков-МСП не доказывает, что **покупатель** является малым предприятием.

В формате настоящей RSS ЕИС от 29.07.2026 заголовок записи может быть «Электронный аукцион №…», а собственно предмет находится в HTML-экранированном поле **«Наименование объекта закупки»** внутри `description`. Исправленный модуль извлекает именно предмет, не подменяет его строкой **«Искомое слово (словосочетание)»**. Источник воспроизводимого примера: https://github.com/stufently/free-zakupki-gov-ru-monitor/blob/main/tests/fixtures/real-eis-rss.xml (MIT, снимок 29.07.2026, это **не действующие на сегодня закупки**).

## Два этапа вместо ложных готовых лидов

**Этап 1 — официальный RSS:** `python -m leadpilot.eis_rss --url <copied_official_RSS> --output exports/eis_research_01.json` (копировать URL из официального интерфейса). Проверить, что `EIS_STATUS=OFFICIAL_FEED_PARSED`, а не ошибочный HTTP/TLS/HTML. RSS не даёт достаточно информации, чтобы автоматически установить ИНН покупателя, актуальный статус и категорию МСП.

**Этап 2 — проверка фактов оператором:** открыть оригинальное извещение и проверить полное юридическое наименование **покупателя**, ИНН, регион, предмет и срок подачи. Создать **локально**, в игнорируемом `exports/`, файл `eis_operator_facts.json` с минимальной структурой:

```json
{
  "mode": "EIS_MANUAL_BUYER_FACTS",
  "items": [
    {
      "source_url": "ТОЧНАЯ_ССЫЛКА_ИЗ_РЕАЛЬНОГО_EIS_JSON",
      "buyer_inn": "ДЕЙСТВИТЕЛЬНЫЙ_ИНН_10_ЦИФР",
      "buyer_region": "Москва",
      "observed_on": "YYYY-MM-DD",
      "procurement_status": "ACCEPTING",
      "deadline_on": "YYYY-MM-DD",
      "scope_status": "EXTERNAL_1C_SERVICE",
      "buyer_identity_note": "Указать, какое официальное извещение подтверждает ИНН и предмет",
      "review_state": "PENDING"
    }
  ]
}
```

Это **схема, не готовые к исполнению данные**. Нельзя придумывать ИНН, статус, дату или ссылку; `ACCEPTING` ставится только после ручной проверки исходного объявления, иначе `UNKNOWN`. `deadline_on` допускает `null`. `scope_status` только `EXTERNAL_1C_SERVICE`, `OTHER_SERVICE`, `UNCERTAIN`. `procurement_status` только `ACCEPTING`, `CLOSED`, `CANCELLED`, `UNKNOWN`. Записи должны быть проверены не более 7 дней назад; в противном случае требуется повторная проверка. `review_state` всегда `PENDING` — импорт не утверждает полномочия менеджера.

Офлайн-проверка (из корня репозитория):

```powershell
.\.venv\Scripts\python.exe -m leadpilot.eis_buyer_review --eis exports/eis_research_01.json --fns exports/sme_first_moscow_50.json --buyer-facts exports/eis_operator_facts.json --output exports/eis_buyer_review_01.json
```

Если нет ни одного проверенного операторами ИНН, используйте `"items":[]` — источник сохраняется как `BUYER_IDENTIFICATION_PENDING`, нельзя выдумывать совпадения.

## Результат и непересекающиеся направления

- `MANAGER_RESEARCH_CANDIDATE_NOT_APPROVED`: ИНН покупателя совпал с уже официально подтверждённой микро/малой компанией Москвы/МО, и вручную указан внешний предмет 1С, действующий статус и срок. **Даже здесь** `crm_ready=false`, контакт не разрешён и нужна проверка живой страницы, юридического основания обращения, действующих клиентов, дублей/стоп-листа, согласование менеджера.
- `OUTSIDE_PILOT_OR_NEEDS_REVIEW`: нет точного официального совпадения в указанной **ограниченной** выборке ФНС, регион противоречив, закупка неактивна или предмет нерелевантен. **Отсутствие в 50 компаниях ФНС не означает, что бизнес крупный**: нужна отдельная официальная проверка нового ИНН. Тендер может быть важным для **самостоятельного канала участия самой «Сервис ИТ»**, но не равен малому B2B-лиду.
- `BUYER_IDENTIFICATION_PENDING`: только RSS-ссылка и предполагаемый предмет, покупатель не проверен.

Система не пишет в корпоративный Битрикс24 и не отправляет сообщения, письма, звонки или контакты в ИИ. **Никаких реальных квалифицированных лидов или сделок этим модулем не подтверждено.** Готовность источника требует получения свежего оригинального RSS, независимого подтверждения отдельных извещений и ИНН, официальной ФНС-категории, согласованной приёмки менеджером и отдельного теста прав CRM.

## Валидация

`tests/test_eis_real_format.py` проверяет структуру HTML-экранированного RSS, типовые аукционные заголовки, ложные совпадения по поисковому слову, отсутствие 1С в предмете. `tests/test_eis_buyer_review.py` проверяет строгий ИНН, недопуск просроченных/отменённых закупок, чужих извещений, самовольной отметки APPROVED и CRM-записей. Эти **синтетические** тесты не заменяют реальную проверку доступа к ЕИС, официальную выгрузку ФНС, полную Windows-регрессию и GitHub Actions (#7). Релиз закрыт до фактической приёмки.
