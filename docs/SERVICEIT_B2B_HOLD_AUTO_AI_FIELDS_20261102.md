# Автозаполнение AI-раздела у новых карточек B2B-Center (HOLD)

## Проблема подтверждена по реальному скриншоту 02.11.2026

В смарт-процессе `Сервис ИТ — AI-сигналы (тест)` появилась новая карточка `ТЕНДЕР / проверка · B2B-Center №4661617`. В ней есть исходный статус `tender-opportunity`, но все девять полей `СЕРВИС ИТ | AI-АНАЛИЗ` пусты. Эта карточка была создана **другим кодом**, чем однократная GigaChat-демонстрация №3.

Фактический активный путь: `.github/workflows/b2b-gmail-to-bitrix-hold.yml` → `leadpilot/b2b_github_to_bitrix.py`. Он авторизован создавать ровно одну HOLD-карточку на официальное уведомление B2B-Center, с глобальной проверкой по точному source ID, журналом GitHub Actions и readback. Раньше `hold_payload` содержал только 10 пользовательских HOLD-полей, без GigaChat, без Score и без AI-отчёта.

## Исправление этого источника

Новый `serviceit_b2b_hold_ai_fields.hold_analysis_fields` **при создании новой HOLD-карточки** формирует и включает во ВСЁ ТЕЛО одного запроса `crm.item.add` ровно девять существующих AI-полей. Все значения описывают ТОЛЬКО подтверждённый факт **получения письма с темой**, а не подтверждённую закупку:

- `AI_STATUS=NOT_RUN_SOURCE_UNVERIFIED`: модель GigaChat на этой стадии не вызывалась.
- Краткий вывод: есть уведомление, источник и потребность ещё не проверены.
- Цитата: буквальная тема письма, помечена «из уведомления, не первоисточник».
- Гипотеза: только направления сервиса из existing `classify_services`.
- Ограничения: нет подтверждённых ИНН, покупателя, даты/статуса, проверки клиентов/дублей, стоп-листа и основания контакта.
- Рекомендация, следующее действие, чек-лист, полный отчёт — конкретная инструкция менеджеру по проверке.
- **Никакого числового Lead Score и зелёного/красного badge**, когда нет проверенных фактов. Цветное поле `UF_CRM_13_SVCIT_AI_SCORE_BADGE` намеренно не заполняется. Иначе менеджер может принять необоснованный 90/100 за реальный лид.

Работающий путь не создаёт дополнительной записи `crm.item.update`: поля прилагаются к *существующему* однократному `crm.item.add` и readback проверяет их все. Предыдущие попытки изменения отдельного поля на DEMO #3 с `UNCERTAIN` НЕ повторяются/не трогаются. Код **не** запускает GigaChat, не меняет задачи, не запускает обзвон, не создаёт дополнительные карточки.

## Нельзя считать это полноценным автозапуском GigaChat

Для полного результата как на карточке №3 нужны отдельные шага: прочитать и **проверить первоисточник**, установить ИНН и дату, проверить ФНС, дубли и клиентов; только потом выполнить детерминированный Score, вызов GigaChat для релевантного подтверждённого evidence в пределах политики конфиденциальности, верификацию цитаты, и безопасную однократную запись заполненных полей по событию. Для остальных источников нужен общий обработчик `onCrmDynamicItemAdd` либо общий сервис обработки до `crm.item.add`. До этого править «один раз и на все источники» неверно.

## Как проходит приёмка

- Python unit tests подтверждают девять полей на каждое B2B HOLD, отсутствие выдуманного Score и GigaChat, запрет неподтверждённых contact flags.
- Существующий mock E2E тест `test_b2b_github_to_bitrix` подтверждает, что GitHub reservation происходит ДО первого POST, а readback проверяет полное содержимое карточки, включая AI-поля.
- Реальную новую карточку и работу Github Actions надо подтвердить отдельным свежим уведомлением; **CI сам не доказывает изменение корпоративного Битрикс**. Историческую карточку №4661617 изменение кода не затрагивает; backfill требует отдельного read-only разбора и approved reconciliation.

### Порядок включения полного AI

1. Принимать события от Bitrix24 только с проверкой `auth.application_token`, домена и `entityTypeId=1062`. Не доверять `data.FIELDS` как полному тексту карточки: event содержит только ID/type.
2. Подтянуть нужные данные через `crm.item.get` после проверки токена, не изменяя карточки.
3. Если source HOLD, сохранить честный STATUS и чек-лист; для реального GigaChat нужно подтверждённое evidence.
4. Выполнить bounded GigaChat с проверкой цитаты и отдельным ограничением приватности, Score без выдуманных фактов.
5. Отдельный outbox и readback с no-retry по неопределённому исходу; защита от повторного события.
6. В общем канбане отобразить Score/badge, когда они реально рассчитаны.
