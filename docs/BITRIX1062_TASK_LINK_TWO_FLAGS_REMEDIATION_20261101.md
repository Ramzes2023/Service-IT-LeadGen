# Bitrix24 №1062: два подтверждённых блокера связи с задачами — 01.11.2026

## Данные корпоративного read-only запуска

Пользователь запустил приёмку на коммите PR #42, получил:

```text
crm.type.getByEntityTypeId: OK; correct_entity_type=true;
    task_link_enabled=false; automation_confirmed_off=true
crm.enum.ownertype: OK
tasks.task.getFields: 401 INSUFFICIENT_SCOPE
crm.item.get: OK
task_created=false; crm_writes=NO; customer_contact=NO
```

**Вывод:** исправление вызова `crm.type.getByEntityTypeId` подтвердилось на живом портале. Связь смарт-процесса с задачами не включена полностью. У использованного вебхука недостаточно REST scope `task` для `tasks.task.getFields`. Доступ к CRM и тестовой карточке #3 работает. Никакая задача пока не создавалась.

## Точные настройки процесса — два независимых признака

В официальной [инструкции по связыванию задач](https://apidocs.bitrix24.ru/tutorials/tasks/how-to-connect-task-to-spa.html) обе опции обязательны:

- `isUseInUserfieldEnabled = 'Y'` — разрешить использовать тип CRM в пользовательских полях;
- `linkedUserFields['TASKS_TASK|UF_CRM_TASK'] = 'true'` — разрешить выбирать процесс в поле CRM конкретной задачи.

В разных ответах REST разрешённая опция может отображаться как `'Y'` или `'true'`; диагностический код учитывает оба варианта.

**Новый read-only результат** выводит раздельно `userfield_use_enabled` и `tasks_task_linked_field_enabled`, затем их общую проверку `task_link_enabled`. Благодаря этому не нужно изменять настройки вслепую.

### Где включить в UI с разрешения администратора

1. Открыть [Bitrix24](https://serviseit.bitrix24.ru) → **CRM → Смарт-процессы → список смарт-процессов** (или соответствующее цифровое рабочее место).
2. Найти существующий **«Сервис ИТ — AI-сигналы (тест)»**. Открыть **настройки самого смарт-процесса**, а не канбан-карточки.
3. Во вкладке **«Привязка к элементам»** / **«Привязка к другим инструментам»** включить его связь с **Задачами**. Если интерфейс отдельно предлагает использование типа в пользовательских полях, включить и эту опцию.
4. Сохранить, проверить, что другие процессы и роботы не изменились, повторить read-only диагностику.
5. Если UI не позволяет настроить связь, администратор может выполнить проверенное `crm.type.update` с внутренним ID типа (полученным из `crm.type.getByEntityTypeId.result.type.id`) и строго двумя нужными полями **по отдельному разрешению**; не запускать произвольные команды изменения на действующем портале.

Официальная статья Bitrix24 по настройке: https://helpdesk.bitrix24.ru/open/18913884/ .

## Второй блокер — scope задачи

В настройках **того же разрешённого входящего вебхука** проверьте раздел прав: требуются CRM (`crm`) и Задачи (`task`). Изменение прав существующего вебхука и идентификация его владельца — корпоративная административная операция. Не присылайте webhook/токен в чат; избегайте доступа «все права».

Даже после включения обеих настроек и scope `task` остаются отдельные gates: действующий user ID Михаила, его права, отсутствие ранее созданной задачи, одноразовая отправка с readback, предотвращение повторов при тайм-ауте и явное разрешение на тестовое создание. Форма «Создайте дело» внутри CRM **не подтверждает** создание задачи.
