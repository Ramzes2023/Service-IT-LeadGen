# Сервис ИТ — автоматическая проверка ФНС-МСП без ручного скачивания

Дата 05.11.2026. Только **реальные новые** карточки `crm.item` смарт-процесса `1062/21`. Это отдельный канал **проверки компаний**, НЕ источник лидов.

## Официальный источник и ограничение достоверности

- ФНС: https://www.nalog.gov.ru/opendata/7707329152-rsmp/ .
- Выпуск реестра МСП на 05.11.2026: `data-10102026-structure-12052026.zip` (10 октября).
- GitHub Actions [42071333939](https://github.com/Ramzes2023/Service-IT-LeadGen/actions/runs/42071333939): **HEAD 200, 2 246 598 554 байта**, скачивания не было.
- Принадлежность к открытому реестру МСП на дату выпуска **не является подтверждением действующего состояния юрлица в ЕГРЮЛ/ЕГРИП**. Нет автоматического разрешения контакта, квалифицированного Lead Score или сверки с корпоративным STOP-листом.

## Подключённый облачный конвейер

1. Каждый день в 03:36 UTC или по строго авторизованному комментарию владельца в Issue #148: `SERVICEIT_FNS_MSP_OFFICIAL_LIVE_ONCE_V1`. GH Actions — best effort.
2. Считать только новые карточки `1062/21` после cutover, проверить контрольную сумму ИНН. Если нет подходящих ИНН — **нет HTTP-запроса к ФНС, нет загрузки 2,25 ГБ**, только служебная сводка без организаций/ИНН.
3. По официальному паспорту ФНС найти свежий датированный ZIP (не старше 45 дней). Строго HTTPS `www.nalog.gov.ru` или `file.nalog.ru`, полный путь и проверка даты. Не переходить на другие домены.
4. Для ещё не проверенных в этом выпуске **до 20 карточек на запуск** загрузить ZIP потоково во временный каталог Github runner. Лимит 3 ГБ ZIP, 16 ГБ распакованных XML, 512 МБ на XML, 100000 членов, DTD/entities/external запрещены. Посчитать SHA256 локально и сверить разбор структуры. Архив удаляется после запуска.
5. Сопоставить полученные ИНН **внутри runner**, не передавая их ФНС в запросах. Для каждого результата — шифрованная HOLD-квитанция на отдельной ветке `serviceit-ai-encrypted-ledger`; имя файла — HMAC, без угадываемого ID/ИНН. Без публичных журналов со списками компаний, ИНН и CRM ID.
6. Существующий `serviceit-stage4-fns-dedup-readonly.yml` читает только собственные завершённые зашифрованные HOLD-квитанции по карточке+ИНН+публикации, чтобы отличить совпадение в МСП от отсутствия совпадения. Квитанция с отсутствующим/ошибочным подтверждением блокирует проверку.
7. Изменения CRM **0**, внешние контакты **0**, запросы иных источников лидов **0**. Формальный score **запрещён** пока не подключён независимый ЕГРЮЛ/ЕГРИП и не утверждены права/полнота CRM, STOP-лист, правовые основания и остальные девять корпоративных доказательств.

## Важно для владельца

Ничего скачивать или запускать в PowerShell не требуется. Архив МСП достаточно большой, поэтому новый обработчик **не** включён в десятиминутный AI-сканер; отдельное суточное расписание предотвращает постоянную загрузку. У GitHub Actions есть ограничения времени, объёма runner и сетевого доступа; отсутствие новых карточек **не проверяет** полный цикл скачивания 2,25 ГБ. При сбое сохраняется `HOLD`, не `VERIFIED`.

Для полной **юридической** автоматизации ЕГРЮЛ/ЕГРИП нужен отдельный разрешённый канал ФНС: промышленный XML-доступ по регламенту ФНС либо официальный электронный подписанный документ по ИНН с независимой проверкой подписи. Публичная поисковая форма `https://egrul.nalog.ru/` не считается документированным промышленным API. Корпоративные STOP и CRM-дубли — отдельные задачи компании; модуль МСП не подменяет их.
