# B2B-Center — постоянная автоматическая обработка, не разовый пилот

9 ноября 2026. ТЗ владельца: B2B-Center должен автоматически передавать все подходящие **новые** IT-закупки в VPS/Bitrix24, с AI и рабочим процессом каждые 5 минут. **Ручная работа на каждой карточке не требуется**; только юридически/фактически сомнительные случаи остаются на HOLD/REVIEW.

## Повторяющаяся схема

B2B-Center → новые Gmail письма → существующий Google Apps Script каждые 5 минут → HMAC-signed HTTPS POST → отдельный VPS receiver → PostgreSQL уникальный inbox → отдельный VPS writer каждые 300 с → exact Bitrix 1062/21 source duplicate → durable POST_UNCERTAIN receipt → один HOLD элемент → exact CRM GET readback → существующий native coordinator / RouterAI + Brave Web + LLM Context + approved Chromium + 9 AI полей / Kanban / задачa / MSP и Score с доказанным HOLD.

### Справедливость и масштабирование

- В Apps Script максимум 4 подписанных уведомления за запуск; остальное сохраняется как PENDING и продолжает передаваться через 5 минут (без кнопки пользователя).
- VPS writer обрабатывает до 4 элементов очереди за цикл; следующие остаются в PG на следующую итерацию.
- Суточный лимит 240 попыток внешнего Bitrix POST — **защитная максимальная нагрузка, не разовое испытание**. После заполнения лимита PENDING автоматически возобновится, когда rolling 24-hour window освободится; лимит нельзя обходить параллельными старыми GitHub writers.
- Любая исходящая CRM POST после записи в PG имеет статус POST_UNCERTAIN до точного подтверждения. Не повторять при сетевой неопределённости.
- Некорректная структура отдельно карантинируется REVIEW и не блокирует все последующие закупки.
- Не создавать автоматические исходящие письма/звонки, не выдавать HOLD за подтверждённого клиента, не обходить корпоративный STOP и отсутствующий платный ФНС.

## Всё ещё обязательные ЕДИНОРАЗОВЫЕ действия установки (не обработка карточек)

Это **одна начальная настройка доступа**, а не еженедельная/дневная ручная работа:

1. Root сервера: наличие общего HMAC в /etc/serviceit/secrets/b2b_ingest_hmac, отдельные права uid 10001, и проверенный Caddy route на порт 127.0.0.1:18781.
2. Контролируемый запуск receiver и writer Docker из отдельного Compose; подготовленный образ B2B уже staged на VPS, но контейнеры пока не запущены.
3. Проверка живого Google Apps Script проекта: импорт последнего Code.gs, сохранение secrets.gs, выполнение activateVpsB2BCenter() один раз. Она проверит signed no-write probe и создаст периодический Gmail триггер каждые 5 минут. Не получать Google OAuth через новое Cloud Console.
4. Сначала source receiver/PG PENDING read-only; потом активация writer и доказательное E2E readback первого нового B2B tender. После успешной проверки **не останавливать** цикл, он остаётся автоматическим.
5. Контроль и уведомление об ошибках: встроенные health/observer + внешние GitHub read-only watchdog; backlog/POST_UNCERTAIN/REVIEW требуют отчётности, а не многократного POST.

### Подтверждение и ограничения

По реальному аудиту VPS 42701407206: CORE/AUX/BUSINESS=YES, Caddy=YES, native 5-min=YES, старые GitHub writers OFF; SOURCE_ROUTE_PRESENT=NO, SUDO_NONINTERACTIVE=NO, HMAC_FILE_VISIBLE=UNVERIFIED, GitHub B2B HMAC secret отсутствует. Образ на VPS staged и smoke PASS: 42701855636.

**Не объявлять источник LIVE**, пока новый receiver, HTTPS, HMAC, Google trigger и первая E2E-карточка не будут независимо подтверждены. Автоматизация начинается после начального безопасного согласования, а затем работает непрерывно.
