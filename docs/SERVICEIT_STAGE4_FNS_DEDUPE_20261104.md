# Этап 4.1 — автоматический контроль ИНН, дублей и ФНС (без STOP-листа)

## Что включено

GitHub Actions `serviceit-stage4-fns-dedup-readonly.yml` запускается по расписанию каждые ~20 минут и по точному owner-комментарию `SERVICEIT_FNS_DUPLICATES_AUTO_READONLY_ONCE_V1` в Issue #148. Используется **реальный корпоративный вебхук** из Secret, без локального ноутбука. Сканирует только новые `1062/21` после cutover, калибрует форму списка старым #3 **только на чтение**, берёт максимум 6 за запуск, справедливо вращает окна.

По каждой карточке:
1. Выполняет точный `crm.item.get`, проверяет дату создания, категорию, ИНН/контрольную сумму.
2. Выполняет `crm.item.list` с фильтром ИНН и категорией по собственной воронке. Если Bitrix игнорирует фильтр, отличается ИНН или результат не полностью постранично прочитан — **UNKNOWN**, а не «дублей нет».
3. Выполняет `crm.requisite.list` для точного ИНН среди доступных контактов/компаний. Найденное совпадение — **HOLD_POTENTIAL_VISIBLE_CRM_DUPLICATE**, даже если воронка чиста.
4. Может проверить **официальный реестр МСП ФНС** через уже существующий parser `serviceit_stage4_fns_msp_snapshot.verify`, но только если корпоративным контролируемым процессом предоставлены *настоящий* архив `SERVICEIT_FNS_MSP_ARCHIVE_PATH`, официальная URL `SERVICEIT_FNS_MSP_PUBLIC_URL` и независимо проверенный SHA256 `SERVICEIT_FNS_MSP_SHA256`. Без них результат `HOLD_FNS_SNAPSHOT_NOT_CONNECTED`; из отсутствия организации в МСП не выводить отсутствие регистрации в ЕГРЮЛ.
5. Вычисляет в памяти предварительный приоритет триажа без AI (это НЕ официальный Lead Score). Результат не раскрывает ИНН/название компании в публичных логах.

**Главный предел:** текущий вебхук не гарантирует полный доступ ко всем компаниям и контактам в CRM. Официальный МСП не доказывает активность в ЕГРЮЛ/ЕГРИП. Промышленное подтверждение активности через ФНС требует отдельного одобренного источника ФНС/официальной выписки (не «секретного» неподтверждённого API). STOP-лист у компании пока отсутствует и отложен по решению владельца — статус всегда `DEFERRED_NOT_CONFIGURED`, это **не** значит «проверка CLEAR».

**Поэтому:** `formal_score_authorized=false`, `score_writes=0`, `crm_writes=0`, `tasks_created=0`; существующий `stage4` полный 9-gate Score writer остаётся закрытым и не переводит такие карточки в verified, не делает контактов. Для реального Score после 8 достоверных этапов и отложенного STOP понадобится отдельная корпоративная политика «предварительная оценка» без разрешения связи; не заменять формальный Score фиктивным числом. Исторические #3/#7 и техподдержка не затрагиваются.
